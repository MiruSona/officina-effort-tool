# 픽셀 그림 작업에서 쓴 피드백 (2026-09-21)

> 반영 (2026-09-21) : README·help 의 `estimate` 표기를 `[옵션…] [소단계…]` 로 고치고, 「서브에이전트 판은 끝난 뒤 메인 세션이 잰다」를 README·SKILL 에 넣었다. 그림 분류·사람 확인 배율은 안 만든다.

픽셀 그림 스프라이트 두 장을 세 판에 걸쳐 그린 일에서 `effort` 를 쓴 기록이다.
앞 문서 넷(`2026-09-20-ProjectMozzi사용피드백.md` · `2026-09-20-서브에이전트구간못잼피드백.md` ·
`2026-09-20-아트작업에서안쓴까닭.md` · `2026-09-20-타일작업피드백.md`)에 이어 쓴다.
거기 적힌 것은 다시 풀지 않고 가리키기만 한다.

## 결론

- **`estimate` 를 한 번 돌려 봤지만 값이 실제와 자릿수가 달라 못 썼다.** 공수 표의 「실제」 칸은 벽시계 손 측정으로 적었다.
- 옵션 차례를 README 표기대로 썼다가 종료 1 로 튕겼다. 표기 한 줄만 고치면 막히지 않는다.

## 막힌 것

| # | 무엇 | 어떻게 됐나 |
| --- | --- | --- |
| 1 | **README 의 `estimate` 표기가 옵션 자리를 거꾸로 읽히게 한다** | README 「자주 쓰는 옵션」에 `effort estimate [소단계...] [--from FILE|-] …` 로 적혀 있어 소단계를 먼저 쓰는 것으로 읽었다. 그대로 `effort estimate 조사:S --human` 을 쳤더니 **종료 1** 이었다. `[옵션…] [소단계…]` 로 적어 주면 한 번에 지나간다 |
| 2 | **서브에이전트 안에서는 자기 판을 못 잰다** | 세션 JSONL 이 아직 안 닫혀 `scan` 대상이 아니다. 앞 문서(`서브에이전트구간못잼피드백`)와 같은 벽이지만, 이번에는 **작업 자체를 서브에이전트가 했기 때문에** 스스로 재려다 시간만 썼다. README 에 「서브에이전트 판은 끝난 뒤 메인 세션이 잰다」 한 줄이 있으면 헛돌지 않는다 |

## 헷갈린 것

| # | 무엇 | 자세히 |
| --- | --- | --- |
| 1 | 그림 작업의 예상이 실제와 8배 벌어진다 | `조사:S 구현:M 검토:M` 이 **합 4분**을 냈다. 실제는 첫 판만 11분, 세 판 합 27분이었다. 그림 일은 「그리고 → 사용자에게 보이고 → 물리면 고쳐 다시 돌린다」 라서 한 묶음에 사람 확인이 끼어든다. 그 기다림이 본줄 벽시계에 안 잡히는 듯하다 |
| 2 | 위와 이어지는 것 | 분류에 **그림 칸**을 따로 두거나, 사람 확인이 끼는 일에 배율을 따로 두면 맞아질 것 같다. `--human` 배율 이야기(진행상황의 「자릿수가 다시 벌어졌다」 줄)와 같은 뿌리로 보인다 |

## 잘 된 것

- **읽기 명령이 아무것도 안 쓴다는 보장**(README 61줄)이 분명해서, 남의 세션과 겹칠 걱정 없이 마음 놓고 돌렸다.
- `estimate` 가 내는 표가 보고의 공수 표에 그대로 붙는 꼴이라 옮겨 적을 일이 없다.
