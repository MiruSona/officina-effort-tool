# 반복 06 갈래 병렬 작업 피드백

- 날짜 : 2026-10-05
- 쓴 곳 : 게임 저장소, 메인 세션 하나 + 서브에이전트 갈래 넷(병렬) + Play 확인 한 판 + 마무리 기록 한 판

## 막힌 것

- **메인 세션 문맥이 압축된 뒤 서브에이전트 mark 「기록 구간」이 실제보다 짧게 나오거나 `—` 로 나왔다.**
  갈래 넷의 구간이 7 ~ 13분으로 찍혔는데, 맡긴 일의 크기(코드 + 프리팹 + 시험)에 견주면 짧다. 줍기 갈래는 `—` 였다.
  그래서 공수 표의 「실제」 칸에 「못 쟀다」가 늘었고, 다음 눈금으로 쓸 값이 안 남았다.
- 바라는 것 둘 :
  1. `mark stop` 이 `—` 를 찍을 때 **왜 못 쟀는지**(묶은 기록을 못 찾음 · 기록이 구간 밖 등)를 한 줄 알려 준다.
  2. 구간이 「찍은 구간」(start ~ stop 시계 시간)보다 눈에 띄게 짧으면 「기록이 일부만 잡혔을 수 있다」 고 경고한다.
- 2026-10-04 `전용화면판1피드백` 의 「압축 뒤 구간」 과 같은 갈래의 문제다. 그때는 서브에이전트 자신의 압축이었고, 이번에는 메인 세션 압축 뒤에 띄운 서브에이전트였다.

## 잘 된 것

- mark start / stop 이 서브에이전트 프롬프트 한 줄로 끝난다. 갈래마다 따로 설명할 것이 없었다.
- `mark start` 출력에 「끝낼 때 : effort mark stop <id>」 가 바로 찍혀 id 를 따로 적어 둘 필요가 없었다.
