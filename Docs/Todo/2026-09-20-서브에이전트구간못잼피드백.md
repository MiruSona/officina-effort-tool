# 서브에이전트 구간을 못 잰 피드백 (2026-09-20)

> 반영 (2026-09-21) : 시각에 시간대 표시(`날짜(+09:00)`·`-07:00`) · 모르는 줄 종류 넷 등록 · 명령 세 벌 표 · 캐시에 없는 묶음 안내 문구를 고쳤다. `mark`·`--live` 와 서브 구간을 총계에 넣는 옵션은 안 만든다.

한 게임 저장소에서 서브에이전트가 WebGL 빌드 한 판을 `effort` 0.1.0 으로 재려던 기록이다.
앞 문서(`2026-09-20-ProjectMozzi사용피드백.md` · `2026-09-20-아트작업에서안쓴까닭.md` · `2026-09-20-타일작업피드백.md`)에 이어 쓴다.
거기 적힌 것은 다시 풀지 않고 가리키기만 한다.

## 결론

- **메인 세션이 서브에이전트에게 맡긴 5분짜리 일(빌드·실측)은 `effort` 로 못 쟀다.**
- 공수 표의 「실제」 칸은 `date` 로 찍은 손 측정으로 적었다.
- 앞 문서들은 「안 썼다」「못 읽었다」였다. 이번에는 **스킬을 찾아 읽고 `scan`·`show` 까지 돌렸는데도** 값이 안 나왔다.

## 막힌 것

| # | 무엇 | 어떻게 됐나 |
| --- | --- | --- |
| 1 | **서브에이전트에서는 스킬이 안 뜬다** | `Tools/EffortTool/README.md` 를 읽어도 서브에이전트의 Skill 목록에 `EffortTool:effort-usage` 가 안 떴다 (`Unknown skill`). 「README 를 한 번 읽으면 뜬다」는 규칙이 서브에이전트에서는 안 통했다. `.claude/skills/effort-usage/SKILL.md` 를 파일로 직접 읽어 풀었다. 메인 세션에서는 서브모듈 파일을 만진 뒤 목록에 떴다 |
| 2 | **「이 작업 한 판의 시작·끝을 잰다」는 명령이 없다** | 세션 JSONL 을 나중에 읽는 방식이라 start/stop 이 없고, 단위가 「사용자 프롬프트 한 개」다 |
| 3 | **`show` 값이 실제와 크게 달랐다** | 해당 작업의 `effort show` 는 벽시계 1분 미만 (본줄 1분 미만 · 서브 —), 표시는 `배경갈래, 순수시간잘림, cost-state없음` 이었다. 실제로는 서브에이전트가 약 7분(빌드 4분 51초) 돌았다. SendMessage 로 이어 붙인 서브에이전트 구간이 안 잡혔거나 턴이 안 닫혀서일 수 있다 — **어느 쪽인지는 확인 못 함** |

서브 구간이 총계 밖이라는 점과 「1분 미만」 눈금 이야기는 앞 문서(타일작업피드백 막힌 것 1·4)에 있다.

## 헷갈린 것

| # | 무엇 | 자세히 |
| --- | --- | --- |
| 1 | 시각이 UTC 인데 표시가 없다 | `list`·`show` 의 `09-20 03:26` 이 한국 시각 12:26 이다. 새벽 작업으로 읽혔다 |
| 2 | `scan --project` 뒤의 경고 문구 | `effort scan --project …` 직후 `list --group mark` 가 「정본의 작업 19건을 캐시에서 못 찾았습니다 (effort scan --all 을 돌려 보세요)」를 냈다. `--project` 로 scan 하면 다른 프로젝트 묶음이 빠져서 나오는 말로 보이는데, 문구에서 그 관계가 안 읽힌다 |
| 3 | 한글 제목이 깨져 잘린다 | 제목이 60자에서 잘릴 때 한글이 바이트 중간에서 잘려 깨진 글자가 찍힌다. 룬 경계로 잘라야 한다 |
| 4 | 모르는 줄 종류 3가지 | scan 이 `artifact-autoreact-ledger` · `artifact-comment-monitor` · `frame-link` 를 알렸다. Claude Code 새 판의 줄 종류다. 같은 셋이 앞 문서(타일작업피드백)에도 나온다 |
| 5 | README 예시에 서브모듈 경우가 없다 | 예시가 `.\bin\effort.exe` 와 `.\EffortTool\bin\…` 두 벌뿐이다. 서브모듈로 붙인 저장소에서 쓰는 `Tools/EffortTool/bin/effort.exe` 경우가 없다 |

## 잘 된 것

- 실행 파일이 이미 있어 바로 돌았다.
- `scan` 이 수 초로 빠르고, 종료 코드와 한 줄 요약이 분명하다 (읽은 세션 3개 · 작업 2,595건).
- `show` 가 「서브 —」와 표시 셋으로 **못 잰 까닭을 숨기지 않았다.** 덕분에 값을 지어내지 않고 「못 쟀다」고 말할 수 있었다.

## 바라는 것

- 서브에이전트 구간을 묶음 시간에 넣는 옵션. 또는 `effort mark start/stop "<이름>"` 같은 손 표시.
- 시각에 시간대 표시 (또는 로컬 시각으로 보여 주기).
- 세션 시작 훅의 「공수 재기」 한 줄 안내 — 앞 문서 둘에 이미 적었다. 서브에이전트에서는 스킬이 안 뜨므로 더 필요하다.
