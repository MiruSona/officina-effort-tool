# 떡 배선 검사 고침 · WebGL 빌드 작업에서 쓴 느낌 (2026-09-21)

게임 저장소에서 UI 코드 몇 군데를 고치고 WebGL 을 한 판 굽는 일에 EffortTool 을 썼다.

## 막힌 것

- `effort estimate 검사고침:구현:S 확인:실측:S 빌드:구현:M` 이 세 칸 모두 **1분 안팎**으로 나왔다.
  실제로는 고치기 7분 · 확인 6분 · 빌드 8분 남짓이었다. 근거 칸은 `실측 n=110` 이라 표본은 넉넉한데
  값이 이렇게 작으면 **공수 표에 그대로 못 쓴다.**
  - 묶음 단위로 재는 것이 기본이라고 README 에 적혀 있는데, `n=110` 은 작업 단위 표본처럼 보인다.
    묶음 표시(`group --add`)가 거의 없는 저장소에서는 자동 묶기가 잘 안 먹는 것 아닌가 싶다.
  - 바라는 것 : 표가 **어느 단위로 잰 값인지**(묶음/작업)를 근거 칸에 같이 찍어 주면
    「이 숫자는 못 쓰겠다」를 바로 알 수 있다.

## 잘 된 것

- `Tools/EffortTool/bin/effort.exe` 로 바로 불렀다. PATH 에 없어도 README 의 명령 앞자리 표가 있어 헤매지 않았다.
- 읽기 명령이라 빌드가 도는 중에 눌러도 아무것도 안 건드렸다.

## 뒤에 더함 (같은 날)

- 이 꼴의 실제 눈금이 나왔다 : **지목된 고침 4건 + WebGL 빌드 + 게시 = 약 19분**
  (서브에이전트 14분 + 사람 쪽 검토·게시 5분, 빌드 자체는 305초). 사람 예상은 55분이었다.
  다음 같은 꼴은 25분으로 잡기로 했다. 기억에도 남겼다.
- `estimate` 가 이 꼴에 1분 안팎을 낸 것과 실제 19분의 간격이 스무 배다.
  **표본 단위(묶음/작업)를 근거 칸에 찍어 주기**만 해도 이 표를 믿을지 말지 바로 가릴 수 있겠다.
