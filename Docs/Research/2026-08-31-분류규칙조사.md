# 분류 규칙 조사 — 미분류 75% 는 왜 나오나

- 날짜 : 2026-08-31
- 대상 : `EffortTool/internal/classify/` · 내장 시드 규칙 · 실제 `~/.claude/projects` 세션 101개 / 작업 1096건
- 성격 : 조사만. 코드는 안 고쳤다.

## 결론

**미분류 75% 의 대부분은 「낱말이 모자라서」가 아니라 「일이 아닌 것을 일로 세고 있어서」다.**
추천은 **1안 — 원인(origin)으로 먼저 갈라내고, 서브에이전트 완료 알림은 같은 세션 앞 작업의 분류를 이어받는 것**이다.
낱말을 더 넣는 것(3안)은 효과가 가장 작다.

| 안 | 미분류 | 손대는 곳 | 한 줄 평 |
| --- | --- | --- | --- |
| 지금 | **75%** | — | 잡담·알림·`!명령` 이 다 미분류로 뭉친다 |
| **1안 (추천)** | **19%** | `collect` + `classify` + 칸 3개 추가 | 실제 데이터로 돌려 본 값. 아래 「모의 결과」 |
| 2안 | 약 55% | `classify` 만 | 알림 이어받기만 넣기. 싸지만 잡담이 그대로 남는다 |
| 3안 | 약 70% | `rules.txt` 만 | 낱말 추가. 미분류의 79% 가 애초에 낱말이 없는 글이라 거의 안 준다 |

1안은 실제 캐시로 규칙을 모의 적용해 본 값이다(스크립트, 코드 반영 아님).

## 1. 지금 분류가 하는 일

`classify.Task` 순서 (설계 문서 4장 그대로) :

1. 서브에이전트 `description` **끝말** → 2. `description` **포함 낱말** → 3. `agentType` (`Explore`=조사 등)
   — 셋 중 하나로 잡히면 **토큰을 가장 많이 쓴 서브에이전트**가 그 작업의 분류가 된다.
4. 서브가 없거나 못 잡으면 **작업 제목**(사용자 프롬프트 첫 줄 60자)에 같은 낱말 규칙
5. 그래도 없으면 `미분류`

낱말은 시드 40개(조사·설계·구현·실측·문서·검토)뿐이고, `agent` 규칙은 `Explore`·`Plan`·`code-reviewer` 셋이다.
**여기 서브에이전트를 안 쓰는 작업은 오직 제목 낱말 하나에 걸려 있다.**

## 2. 실측 재확인

```
effort scan --all → 세션 101개 · 작업 1096건 · 줄 25425개
effort stats --by class → 작업 1096건 · 미분류 75% (823건) · 서브기록없음 15%
```

분류된 273건 중 **211건(77%)** 이 서브에이전트 신호로 잡혔다. 즉 **지금 분류기는 사실상 「서브에이전트 description 분류기」**다.
`agentType` 은 요즘 거의 다 `general-purpose` 라 3번 규칙은 거의 안 걸린다(미분류 작업에 붙은 서브 59개 전부 `general-purpose`).

## 3. 미분류 823건을 손으로 묶어 보면

표본이 아니라 **823건 전수**를 규칙식으로 묶은 것이다.

| B. 짧은 맞장구 | 124 | 15% | 4.1h | 「좋아 그러면」 「아하 알겠어」 같은 한두 마디 |

- 서브가 붙어 있는데도 미분류인 건 34건뿐이다. `desc` 가 「v0.4 갈래 A — …」 「물결2-2C …」 처럼 **우리 프로젝트 은어**여서 낱말이 안 걸린다.

(제목 표본은 성격만 보이게 줄였다. 개인 정보·구매 내역·기기 정보가 든 줄은 싣지 않았다.)

## 4. 쓸 수 있는 신호 — JSONL 실물 확인

최근 세션 6개의 줄을 훑어 실제로 있는 칸만 적는다.

| 신호 | 어디에 | 쓸모 |
| --- | --- | --- |
| `origin.kind` | user 줄 | `human` / `task-notification` / `peer`. **A·J 를 100% 정확히 가른다.** 이미 `model.Task.Origin` 에 들어 있다 |
| 제목 접두 `‹bash-input›` `‹command-message›` `/compact` `‹local-command-caveat›` | 제목 | F 를 정확히 가른다 |
| `message.content[].type=="tool_use"` 의 `name` | assistant 줄 | `Write/Edit`·`Agent`·`Read/Grep`·`Bash` 구분. **일했나 안 했나**는 잘 가른다 |
| 같은 `tool_use` 의 `input.file_path` | assistant 줄 | `.md` 냐 코드냐. 미분류가 만진 경로는 md 78 · 코드 10 뿐이고 나머지는 셸(`cd`·`mem`·`git`) |
| `isSidechain` | 모든 줄 | 서브에이전트 줄 걸러내기 |
| 세션 안 앞 작업의 분류 | 캐시 | **알림 321건 중 316건(98%)** 이 같은 세션에 이미 분류된 앞 작업을 갖는다 |
| `attributionSkill` · `attributionAgent` · `gitBranch` | user/assistant 줄 | 아직 안 씀. 스킬 이름으로 분류 힌트를 줄 수 있다 |

주의 : **도구 이름만으로 조사/설계/구현을 가르는 것은 안 된다.** 분류된 작업은 대부분 `Agent` 호출 하나로 끝나서
(조사 41/79 · 구현 50/75 · 문서 38/63) 도구 조합이 같다. 도구는 **「일 vs 대화」 판정**에만 쓴다.

## 5. 후보 세 개

### 1안 (추천) — origin 으로 갈라내고 알림은 이어받기

칸 셋을 새로 둔다 : **`대화`** · **`도구실행`** · **`잡무`**. (기본 `stats`·`estimate` 에서는 빼고, `--all` 로만 본다)

1. `origin` 이 `task-notification`·`peer` → **같은 세션 직전에 분류된 작업의 분류를 물려받는다.** 앞이 없으면 미분류.
2. 제목이 `‹bash-input›`·`‹command-message›`·`/…`·`‹local-command-caveat›`·`/loop` 깨우기 → `도구실행`
3. 도구 호출 0 · 서브 0 → `대화`
4. 제목에 커밋·푸시가 있고 쓰기 도구가 없으면 → `잡무`
5. 남은 것은 지금 규칙 그대로

**모의 결과(전체 1096건)**

| 칸 | 건수 |
| --- | --- |
| 대화 | 208 (19%) |
| **남은 미분류** | **210 (19%)** |
| 이어받기로 채워진 것 | 316 (조사 80 · 문서 92 · 구현 82 · 검토 28 · 설계 21 · 실측 13) |
| 도구실행 | 60 |
| 잡무 | 29 |
| 원래 분류대로 | 273 |

- 장점 : 미분류 75%→19%. **`stats` 의 시간이 제 칸으로 간다**(알림 29h 가 실제 분류로 이동). `origin` 은 이미 캐시에 있어 재스캔이 싼다.
- 단점 : 도구 호출을 보려면 `collect` 가 `tool_use` 이름을 세어 캐시에 한 칸(`tools`) 더 넣어야 한다 → **캐시 판 올리고 `--rebuild` 한 번**.
- 위험 : 이어받기는 「알림 시간이 그 일의 시간」이라는 가정이다. 한 세션에서 갈래를 여럿 돌리면 마지막 분류 쪽으로 쏠린다. `class_by` 에 `이어받기` 를 남겨 나중에 걸러 볼 수 있게 한다.

### 2안 — 이어받기만 (규칙 파일·분류기만 손봄)

`origin` 기반 이어받기 + `도구실행` 접두 규칙만 넣는다. 캐시 판 안 바뀐다.
미분류 75%→약 55%. 싸고 위험이 적지만 **대화 405건이 그대로 미분류에 남아** p50 이 여전히 오염된다.

### 3안 — 낱말 늘리기

`rules.txt` 에 은어(`갈래`, `물결`, `v0.x`)와 잡무 낱말을 더 넣는다.
미분류 75%→약 70%. **미분류의 79% 가 낱말이 아예 없는 짧은 대화·알림**이라 천장이 낮다. 1안을 넣은 뒤 남은 210건을 줄이는 보조 수단으로만 쓸 것.

## 6. 1안을 넣어도 남는 210건

표본을 보면 세 가지다.

- **웹 검색으로 값을 알아본 상담** — `WebSearch`/`WebFetch` 만 쓴 작업. → `조사` 로 볼 수 있다(규칙 하나 추가).
- **한 줄 명령 대행** — 「`mem index` 돌려 줘」 처럼 셸 한 번. → `도구실행` 으로 넓히면 잡힌다.
- **진짜 애매한 것** — 「이 구조가 문제가 있어」 같은 이어지는 대화 중 파일을 몇 개 읽은 것. 사람이 봐도 애매하다. 미분류로 두는 게 맞다.

## 7. 못 한 것

- 코드는 안 고쳤다. 위 숫자는 캐시에 규칙을 모의 적용한 것이라 **실제 구현 뒤 값은 몇 % 다를 수 있다.**
- `attributionSkill` 을 분류 신호로 쓰면 얼마나 늘어나는지는 안 재 봤다.
- 이어받기가 시간 배분을 왜곡하는지(같은 세션 여러 갈래)는 표본으로만 봤고 수치로 안 쟀다.
