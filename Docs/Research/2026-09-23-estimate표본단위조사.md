# estimate 표본 단위 조사 (2026-09-23)

`effort estimate` 가 실제보다 스무 배 작게 나오는 까닭을 캐시로 재 봤다. 코드는 안 고쳤다.

## 결론

- **뿌리 : 표본이 「메인 세션 본줄 묶음」인데, 이 저장소의 일하는 방식에서는 메인 본줄에 일이 거의 없다.**
  메인은 지시하고 결과를 받아 짧게 답할 뿐이고, 실제 일은 서브에이전트 구간에서 돈다.
  그 구간은 결정(2026-09-04)에 따라 벽시계에 안 들어간다. 그래서 묶음 중앙값이 **1.7분**이다.
- 묶음이 「30분 간격 자동 묶기」로 잘게 쪼개지는 것은 곁가지다. 묶음 중앙은 작업 2개이고,
  2분 미만 묶음이 **55~60%** 인데 그 절반은 서브에이전트 완료 알림(`system`)에 짧게 답한 묶음이다.
- 예상하는 쪽은 **서브에이전트가 자기 한 판의 소단계**를 잰다. 표본(메인 본줄)과 예상 대상(서브 판)이 다른 물건이다.
- **추천 : (a) 근거 칸에 표본 단위와 중앙값을 찍는다 — 「서브 포함 중앙」 한 칸까지 같이.**
  숫자를 바꾸지 않고, 자릿수가 어긋났음을 표 안에서 바로 보이게 한다.
  서브 구간을 표본에 넣을지(아래 (e))는 09-04 결정을 뒤집는 일이라 사람이 정한다.

## 표본 경로 (코드)

- `cmd_estimate.go` `samplesFor` → 기본 `--unit group` → `buildGroups` → `group.Build`.
  `groups.txt` 에 적은 묶음(지금 2개)이 먼저, 나머지는 **같은 세션 안에서 앞 작업 시작과 30분 안쪽**이면 한 묶음.
- 묶음 벽시계 = 안에 든 작업 **본줄 구간의 합집합**. 서브 구간은 `AgentWallMs` 에만 따로 남는다.
- `estimate.New` 는 일 칸·`cost-state없음` 아님·120일 안쪽만 남긴다. **프로젝트 가리기는 없다** —
  캐시(`~/.effort`)가 하나라 이 저장소·게임 저장소·벤치 판이 한 표본에 섞인다.
  게임 저장소에서 돌린 `estimate` 가 이 저장소와 **같은 값·같은 n** 을 낸 것으로 확인했다.
- 표시 `render.Minutes` 는 분 아래를 **버린다** (1.8분 → 「1분」). 작은 값이 더 작아 보인다.
