# 메인 세션 mark 「묶기없음」 원인 조사 (2026-10-07)

메인 Claude 세션이 직접 친 `effort mark start` 가 늘 `묶기없음` 이 되는 까닭을 실제 기록 파일로 캤다. 코드는 안 고쳤다.

## 결론

- **뿌리 : 메인 세션은 `mark start` 를 부른 tool_use 줄을, 그 도구가 도는 동안 아직 기록 파일에 안 써 둔다.**
  exe 가 파일 끝을 읽을 때 그 줄이 없으니 못 찾는다. 서브에이전트 파일은 도구가 돌기 전에 줄이 이미 써져 있어 잘 묶인다.
- 찾는 창(2분)·명령 글 판정·경로 꼴(`./` 와 `.\`)·256KB 끝 읽기는 **원인이 아니다.**
  같은 파일을 그 줄까지 잘라 다시 돌리면 그대로 묶인다 (아래 「되짚어 돌리기」).
- 메인 세션 mark start 는 지금까지 **5번뿐이고 4번 실패**했다. 붙은 1번은 **같은 이름이 앞 턴에 이미 써져 있던** 우연이다.
- `mark stop`·`show` 를 인자 없이 치는 길도 메인에서는 같은 까닭으로 못 고른다.
- **추천 : 「미뤄 묶기」 — `묶기없음` 인 mark 를 stop·show·list 때 시각으로 다시 찾아 묶는다.** 공수 M.
  그 전에는 지금 스킬 규칙(「서브에이전트 mark 를 정본으로」) 그대로 피한다.

## 묶기는 무엇을 어떻게 찾나 (코드)

`cmd/effort/cmd_mark.go` `markStart` → `bindOwnFile` → `findCallers` → `scanCallers`.

1. 찾을 폴더 : 지금 폴더로 만든 slug(`~/.claude/projects/<slug>/`). 못 찾으면 다른 프로젝트 폴더 전부를 한 번 더 본다.
2. 후보 파일 (`recentFiles`) : 그 폴더의 `*.jsonl`(메인 세션 파일)과 `<세션>/subagents/agent-*.jsonl`(서브에이전트 파일) 중
   **수정 시각이 지금 ±2분 안**인 것. 메인 파일도 후보에 든다 — 폴더 문제는 없다.
3. 파일 끝 256KB 를 읽어 (`collect.FindToolUse`) `"tool_use"` 가 든 assistant 줄만 푼다.
   그 중 **Bash·PowerShell 도구의 `command` 칸**에 `mark start` 와 바로 뒤 이름(따옴표 벗김, 이름 뒤는 낱말 끝)이 있으면 맞다 (`MatchMarkCommand`).
4. 맞은 파일이 1개면 묶고, 0개면 `묶기없음`, 2개 이상이면 `묶기모호`.

`effort.exe` 앞의 경로 꼴은 판정에 안 든다 — 「`mark start`」 낱말부터 본다.

## 실제 파일로 확인한 것

### 메인 세션 (`<세션A>`)

메인 파일 `~/.claude/projects/<slug>/<세션A>.jsonl` 의 해당 줄 (시각은 UTC, +9 가 한국 시각):

| 줄 | 시각 | 무엇 |
| --- | --- | --- |
| 196 | 08:25:43.541 | assistant thinking |
| 197 | 08:25:44.680 | **assistant tool_use Bash** `./EffortTool/bin/effort.exe mark start "2-effort-steps 손 시험" 2>&1 \| tail -5` |
| — | 08:25:45.201 | exe 가 찍은 mark 시각 (`marks.txt`) → `묶기없음` |
| 198 | 08:25:45.468 | tool_result (「묶기없음」 글) |

- 명령 글에 `cd … &&` 는 없었다. `./` 꼴 그대로이고 판정에는 맞는 꼴이다.
- 줄 길이는 2~9KB 라 256KB 끝 읽기 안에 넉넉히 든다. 줄 195(08:25:43)가 막 써져 수정 시각도 2분 안이다.
- 그런데도 못 찾았다 → 그 순간 파일에 줄 197 이 없었다고 본다.

### 되짚어 돌리기 (결정적 시험)

메인 파일을 잘라 가짜 뿌리에 넣고 같은 이름으로 `mark start --projects <가짜> --home <가짜> --project <slug>` 를 돌렸다.

| 잘라 둔 끝 | 결과 |
| --- | --- |
| 줄 196 까지 (tool_use 줄 없음) | `묶기없음` |
| 줄 197 까지 (tool_use 줄 있음) | **묶음** — `<slug>/<세션A>` |

판정 코드는 맞다. **파일에 그 줄이 있었나 없었나** 하나로 갈린다.

### 서브에이전트는 왜 되나

같은 세션의 서브에이전트 파일 넷(`<세션>/subagents/agent-*.jsonl`) 모두 mark start 가 묶였다.
tool_use 줄 시각과 exe 시각의 틈은 0.6~0.9초로 메인(0.5~1.0초)과 비슷하다. **틈이 아니라 쓰는 때가 다르다.**
서브에이전트는 tool_use 줄을 도구 실행 전에 파일에 쓰고, 메인은 도구가 끝난 뒤(늦어도 다음 몇 초 안)에 쓴다.

Claude Code(2.1.292) 실행 파일 안을 보면 기록은 큐에 넣고 100ms 마다 비우는 구조이고,
메인 세션 줄은 넣기 전에 중복 검사(세션 메시지 읽기)를 기다리는 길이 따로 있다. 다만 **정확히 어느 때 쓰는지는 확인 못 했다** — 위 실측이 근거다.

### C 를 고를지 정하는 실험 (메인 세션이 한 번 돌리면 된다)

메인 세션에서 Bash 도구 한 번에 아래를 친다. 명령 글 자체에 `probe-7f3a` 가 들어 있다.

```
powershell -NoProfile -Command "Start-Sleep 3; (Select-String -SimpleMatch 'probe-7f3a' -Path $HOME\.claude\projects\<slug>\<세션id>.jsonl).Count"
```

0 이 나오면 도구가 도는 동안엔 줄이 안 써진다 → C 는 버린다. 1 이상이면 C 가 싸게 된다.
