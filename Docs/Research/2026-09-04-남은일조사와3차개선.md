## 2. 조사에서 찾은 것

### 2-1. 벽시계를 본줄만으로

벽시계 값은 세 개다 — 본줄(MainWallMs) · 서브(AgentWallMs) · 둘의 합집합(WallMs).
09-01 에 합집합을 정본으로 삼았는데, 실물에서 본줄 28.8h 대 서브 137.6h 로 서브가 5.7배였다.
오래 사는 갈래 하나가 총계를 통째로 끌어올린다.
되돌릴 자리는 `internal/collect/session.go:241` 한 줄(합집합 → 본줄)과 `internal/group/group.go:192-199`(묶음에 서브 구간을 넣던 자리) 둘뿐이다.
벽시계가 줄면 순수시간을 벽시계로 자르는 불변식(session.go:216-219)에 걸리는 건수가 늘 수 있어 같이 봐야 했다.
WallMs 는 스캔 때 캐시 파일에 적히는 값이라 캐시 판을 안 올리면 옛 값과 새 값이 섞인다.

### 2-2. 배율이 두 군데로 갈라져 있던 함정

**코드 기본값과 사용자 rules.txt 의 배율이 서로 다른 값이었다.**
코드 기본값(`internal/classify/rules.go:277-295`)은 옛 값 S 0.3 / M 1.0 / L 2.4 / XL 5.0 인데,
실측해서 고친 새 값(0.16 / 1.0 / 4.46 / 19.41)은 사용자 기계의 `~/.effort/rules.txt` 에만 들어 있었다.
rules.txt 는 있으면 절대 안 덮기 때문에, 새 기계에서 처음 돌리면 옛 배율이 나온다.
게다가 재측정 절차는 설계 문서에 글로만 적혀 있고 명령이 없어서 사람이 손으로 백분위를 세야 했다.

### 2-3. list 와 estimate 의 표본이 달랐다

같은 `gap:30m` 으로 묶어도 `list --group` 은 279 묶음, `estimate` 는 484 묶음이 나왔다.
까닭은 거르는 차례가 반대여서다 — list 는 일 칸만 먼저 거른 뒤 묶고(`cmd_list.go:32`),
estimate 는 다 묶은 뒤 묶음 분류가 일 칸인 것만 고른다(`cmd_estimate.go:46`).
actual 도 estimate 쪽을 따르고 있어서, 외톨이는 list 하나였다. estimate 쪽을 정본으로 삼기로 했다.

### 2-4. 앞말이어짐 병목은 낱말이 아니었다

「지금」「아」「그러면」처럼 앞 이야기를 잇는 말로 시작하는 작업은 앞 작업의 분류를 물려받는다.
그런데 오늘 자료에서 미분류 76건 중 26건이 **이미 등록된 낱말로 시작하는데도** 안 잡혔다.
막은 것은 낱말이 아니라 조건이었다 — 22건이 「바로 앞 작업이 일 칸이 아님」(`classify.go:114`)에 걸렸다.
앞이 대화 10 · 미분류 8 · 도구실행 3 · 잡무 1. 낱말을 아무리 늘려도 안 풀린다.
진짜 약은 「바로 앞」이 아니라 **「가장 가까운 앞 일 칸」**을 보게 하는 것이다.

### 2-5. rules.txt 변경 감지와 human 배율

scan 은 판 번호와 파일 목록만 보고 다시 훑을지 정한다(`internal/store/scanstate.go:21-25`).
rules.txt 를 고쳐도 모르기 때문에 사람이 `--rebuild` 를 기억해야 했다. sha256 지문 한 칸이면 된다.
함정은 차례다 — scan 이 rules.txt 에 빠진 종류를 덧붙이므로, 해시는 **덧붙인 뒤에** 재야 한다.
human 배율(사람이 잰 시간 대 계산값)은 쌓아 둔 파일 자체가 없어 지금은 못 잰다.

## 3. 바꾼 것

- **벽시계** — `session.go` 에서 WallMs 를 MainWallMs 로, `group.go` 에서 묶음에 서브 구간을 넣던 자리 삭제. 캐시 판 3 → 4.
- **표시** — `show` 와 `list --group` 표에 「서브(참고)」 칸을 뒀다. 값은 버리지 않고 참고로만 보여준다.
- **표본 통일** — `list --group` 을 estimate 와 같은 차례(다 묶고 묶음 분류로 고름)로 바꿨다.
- **앞말이어짐** — 낱말 13개를 더하고, 물려받을 앞 작업을 「가장 가까운 앞 일 칸」으로 바꿨다.
- **새 명령 `effort rules --measure`** — 배율과 시드를 코드가 직접 재서, rules.txt 에 붙여 넣을 줄을 찍어 준다. 읽기 전용이라 파일은 안 고치고, 표본 12건이 안 되는 분류는 아예 안 낸다.
- **`effort scan`** — rules.txt 가 바뀌면 `--rebuild` 없이 알아서 전면 재분류한다.

## 4. 남은 것과 함정

- **estimate 값이 사람 시간과 자릿수가 다르다** (구현:L = 4분).
  까닭은 이렇다 — 서브에이전트가 도는 동안 메인 세션은 비어 있고, 끝났다는 알림이 오면 그것이 새 작업으로 잡힌다.
  그래서 기다린 시간이 「작업 사이 대기」로 빠져 버린다. 묶음 벽시계는 작업 구간의 합집합이라 그 빈 곳이 안 들어간다.
  human 배율이 잡히기 전까지는 **순서와 크기 차이를 보는 용도로만** 쓴다 (caution 20260904-b6c09b4f).
- human 배율 재측정 — `group --add` 표시 + `actual --from`. 회차 15~20건 쌓인 뒤에.
- 검토 분류 시드 — 표본이 12건을 넘으면 `rules --measure` 로 낸다.
- `~/.effort/rules.txt` 의 새 contfirst 낱말 13개는 기본값 덧붙이기가 안 더한다(있는 종류는 안 덮음).
  사용자가 손으로 넣거나, rules.txt 를 지워 기본값으로 다시 만들어야 한다.
- 옛 rules.txt 백업 : `~/.effort/rules.txt.bak-2026-09-04`
- `mem review --kind basis` 로 사람이 판정할 것 1건 (20260901-b4d42ea1)
