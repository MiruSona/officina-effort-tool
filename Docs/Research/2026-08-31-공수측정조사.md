# 공수 측정 툴(EffortTool) 조사

> 2026-08-31. Opus 서브에이전트 조사 (실물 JSONL 확인 + 웹 확인). 벽시계 약 6분.

## 결론 먼저

**LLM 토큰 0으로 측정·표 생성이 완전히 가능하다.** Claude Code 가 이미 모든 것을 로컬 JSONL 에 적고 있다. 훅도, 텔레메트리도, AI 호출도 필요 없다 — **JSONL 을 읽는 순수 파서 하나면 끝**이다.

최선의 데이터 원천 조합:

1. **주 원천** : `~/.claude/projects/<슬러그>/<sessionId>.jsonl` + 그 옆 `<sessionId>/subagents/agent-*.jsonl` — 토큰·시각·모델·에이전트 종류 전부 있음
2. **보조(경계 자르기)** : 같은 파일의 `type:"system", subtype:"turn_duration"` 줄 — Claude Code 가 **직접 잰 턴 벽시계 ms**
3. **검산용** : `type:"cost-state"` 줄 — 세션 총계(비용·총시간·모델별 토큰)의 정답값
4. 훅은 **불필요** (토큰·시간을 안 준다)

## 1. JSONL 구조 (실물 확인, Claude Code 2.1.251 기준)

### 위치와 슬러그 규칙

- 폴더 : `~/.claude/projects/<슬러그>/`
- 슬러그 = **cwd 절대경로에서 `\` 와 `:` 를 `-` 로 바꾼 것**. `C:\Mirusona\Project\...` → `C--Mirusona-Project-...`
- 파일 : `<sessionId>.jsonl` (UUID). 각 줄에 `cwd` 가 들어 있어 슬러그 규칙 없이도 역추적 가능

### 서브에이전트 — 별도 파일이다 (가장 중요한 발견)

서브에이전트 기록은 메인 JSONL 에 안 섞이고 하위 폴더로 빠진다.

```
<sessionId>.jsonl                                 ← 메인만. isSidechain 전부 false
<sessionId>/subagents/agent-<agentId>.jsonl       ← 사이드체인. isSidechain 전부 true
<sessionId>/subagents/agent-<agentId>.meta.json   ← 이 에이전트가 누구였나
<sessionId>/tool-results/<id>.txt                 ← 큰 툴 결과 떼어낸 것
```

`meta.json` 실물 — 공수 분류의 핵심 열쇠:

```json
{"agentType":"Explore","description":"mem type 정의 위치 조사","toolUseId":"toolu_01U7…","spawnDepth":1,"model":"opus"}
{"agentType":"general-purpose","description":"mem type 표 toml 분리 구현","toolUseId":"toolu_015F…","spawnDepth":1,"model":"opus"}
```

- `description` = Task 툴에 넘긴 한 줄 설명 → **"조사/설계/구현" 분류를 끝말에서 뽑을 수 있다**
- `toolUseId` = 메인 transcript 의 Task tool_use 블록과 잇는 열쇠
- `spawnDepth`(관찰값은 전부 1) · `model`(opus/sonnet)
- 서브에이전트 줄에만 붙는 필드 : `agentId`, `attributionAgent`, `isSidechain:true`. `sessionId` 는 부모 것을 그대로 쓴다

**주의(과거 버전)** : 2.1.235~2.1.239 세션에는 `subagents/` 폴더가 있는 것과 없는 것이 섞여 있다. **옛 세션의 서브에이전트 기록은 아예 없을 수 있다** — 폴더가 없으면 메인만 세는 폴백이 필요하다.

### assistant 줄 실물 (쓸 만한 필드)

```json
{"isSidechain":false,"requestId":"req_011CeZ…","type":"assistant","uuid":"68539c7b-…",
 "timestamp":"2026-08-31T00:01:28.507Z","effort":"medium","sessionId":"0240547a-…",
 "cwd":"C:\\Mirusona\\…","version":"2.1.251","gitBranch":"main",
 "message":{"model":"claude-fable-5","id":"msg_011CeZ…","role":"assistant","stop_reason":"end_turn",
   "usage":{"input_tokens":2,"cache_creation_input_tokens":51359,"cache_read_input_tokens":0,
     "output_tokens":261,"output_tokens_details":{"thinking_tokens":71}}}}
```

`timestamp`(ISO8601 UTC ms) · `message.usage.*` · `message.model` · `effort` · `requestId` · `message.id` · `thinking_tokens`.

### 줄 종류와 쓸모

| type | 쓸모 |
| --- | --- |
| `assistant` | **토큰·시각·모델** — 주 원천 |
| `user` | 사용자 요청 시각, `promptId` |
| `system` (subtype `turn_duration`) | **`durationMs` + `messageCount`** — Claude Code 가 잰 턴 벽시계 |
| `cost-state` | **세션 총계 정답값** (아래) |
| `ai-title` | 세션 제목 — 표 라벨감 |
| 그 밖(`last-prompt`·`mode`·`file-history-*` 등) | 공수와 무관 |

`cost-state` 실물 요약 : `totalCostUSD` · `totalDuration`(벽시계 ms) · `totalAPIDuration`(LLM 이 돈 시간) · `totalToolDuration`(툴 실행 시간) · `modelUsage`(모델별 토큰·비용).
기존 눈금 기준 "AI 가 실제로 붙잡고 있던 시간" = `totalAPIDuration + totalToolDuration`, 사용자 대기 포함 벽시계 = `totalDuration`. **기존 공수기록의 "사용자 답 기다린 시간 제외" 규칙을 코드로 그대로 구현할 수 있다.**

### 작업(요청~완료) 경계 자르기 — `promptId` 가 정답

한 사용자 요청에서 파생된 모든 줄(중간 tool_result 포함)이 같은 `promptId` 를 공유한다. 서브에이전트 파일 줄에도 `promptId` 가 붙어 **부모 작업에 서브에이전트를 붙일 수 있다.**

작업 하나의 값 = `promptId` 로 묶어서

- 시작 = 첫 `user` 줄 timestamp, 끝 = 마지막 줄 timestamp → 벽시계
- 순수 작업시간 = 그룹의 `turn_duration.durationMs` 합
- 토큰 = 그룹 `assistant` 줄 usage 합 (아래 중복 제거 필수)

## 2. 함정 — 스트리밍 중복 (놓치면 2.7배 뻥튀기)

같은 `(requestId, message.id)` 쌍이 **2~10번 반복 기록된다** (스트리밍 중간 스냅샷).

실측 (한 세션 메인 파일): 그냥 합산 output 185,796 → 중복 제거 후 68,094 (**2.7배 차이**).
어느 것을 남기냐도 갈린다 — output_tokens 는 스트리밍 중 단조 증가하므로 **last-wins(=max-wins)** 가 맞다. first-wins 는 3배 과소집계였다. `cache_read`/`cache_creation` 은 전략과 무관하게 같았다.

### 검산 결과

- 작은 세션 : JSONL 합산과 `cost-state` **완전 일치**
- 큰 세션 : JSONL(메인+서브, last-wins)이 `cost-state` 보다 **약 45% 과소** — 까닭 확정 못 함 (중첩 서브에이전트 누락, compaction, 하위 세션 분산 중 하나로 추정). `cost-state` 의 haiku 항목(제목 생성 등)은 transcript 에 아예 안 남는다.
- 모델 이름이 `cost-state` 는 `claude-opus-5[1m]`, assistant 줄은 `claude-opus-5` 로 **다르다** — 정규화 필요.

→ 세션 총계는 `cost-state`, 작업·에이전트별 쪼개기는 JSONL 합산을 쓰되 "쪼갠 합 < 총계" 임을 인정하고 나란히 보여 주는 것이 정직하다.

## 3. 훅 — 거의 쓸모없다

공식 문서 확인: **어느 훅 이벤트도 토큰·소요시간·비용을 stdin 으로 주지 않는다.** 공통 필드는 `session_id`·`prompt_id`(v2.1.196+)·`transcript_path`·`agent_id`·`agent_type` 등. `transcript_path` 는 "may lag current turn" 명시 — Stop 훅에서 바로 읽으면 마지막 줄이 없을 수 있다.

이 PC 실제 상태:

- `~/.claude/settings.json` → `"hooks": {}` 비어 있음 (Orca 가 관리 — 여기 걸면 날아간다)
- 프로젝트 `.claude/settings.json` → mem 의 `SessionStart`·`SubagentStart` 훅이 걸려 있음 (살아 있다)

→ **훅 없이 JSONL 만으로 충분.** 굳이 쓴다면 프로젝트 settings 에만, 그리고 "SessionStart 훅은 하나로 합친다"(mem 20260822-d57c5a52) 결정 때문에 추가는 피하는 게 낫다.

## 4. OpenTelemetry — 채택 안 함

`CLAUDE_CODE_ENABLE_TELEMETRY=1` 로 토큰 메트릭이 나오지만 exporter 는 `otlp`/`prometheus`/`console` 뿐 — **로컬 파일 exporter 가 없어 상주 프로세스(collector)가 필요**하다. mem 의 기존 결정 "데몬도 상주 프로세스도 안 쓴다"(20260822-ed9614cf)와 어긋난다. JSONL 에 같은 값이 더 잘게 있으므로 채택하지 않는다.

## 5. 기존 오픈소스

- **ccusage** (npm) : 같은 JSONL 을 읽어 **일별·모델별 비용** 리포트. 중복 제거는 requestId 기준 last-wins. 관련 이슈(#888, claude-code #28197 "input_tokens 는 placeholder")가 우리 실측과 일치.
- **차별점** : 기존 툴은 전부 일/모델 단위 비용 리포트다. **작업(promptId) 단위·서브에이전트 단위·조사/설계/구현 분류별 공수**를 내는 툴은 없다. EffortTool 의 자리는 여기다.

## 6. 저장소 안 기존 공수 자료와 잇기

- 표 형식 : `| 소단계 | 예상 | 실제 | 상태 |` + `**어긋난 까닭**` 한두 줄 (`Docs/History/공수기록.md`)
- 눈금 규칙 : 실측 든 소단계 ×2 / 동결→재측정 두 바퀴 / 오래 걸리는 측정은 먼저 걸어 둔다
- 실측 누적 배율 : 촘촘한 설계의 코드 구현 = 사람 눈금 ×0.1~0.05 · 문서 구현 ×0.5 · 설계·조사 ×0.7 · 실측은 그대로 · Opus 웹조사 1건 = 벽시계 약 10분
- 재는 기준 (mem 눈금표 20260822-12ba022f · 20260822-adad8ce3) : **AI 가 붙잡고 있던 시간만, 분 단위** — `turn_duration` 합으로 그대로 구현 가능
- 분류 축 : `meta.json.description` 끝말("…조사"/"…설계"/"…구현") + `agentType` + `model` 로 조사/설계/구현/실측/문서 5분류가 코드만으로 거의 자동. 애매하면 "미분류".

## 확인 못 한 것

- 큰 세션에서 JSONL 합산이 cost-state 보다 45% 적은 정확한 까닭
- `cost-state` 가 언제 쓰이는지 (세션당 1~2회 관찰, 진행 중 세션엔 없을 수 있음)
- `spawnDepth: 2` 이상(서브의 서브) 기록이 어디 남는지
- compaction 세션의 토큰 기록 방식
- OTel 파일 exporter 부재는 문서 요약 기반 (최신판 원문 미확인)
- ccusage 소스 코드 직접 확인 못 함 (이슈·문서 요약만)
