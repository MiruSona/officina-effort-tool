# 분류 규칙 개선 설계 — 미분류 75% → 19%

> 2026-08-31. 근거는 `EffortTool/Docs/Research/2026-08-31-분류규칙조사.md` (1안 채택).
> 앞 설계 `2026-08-31-공수측정설계.md` 를 **덮지 않고 4장(분류 규칙)만 갈아 끼운다.**
> 규칙 : `AGENTS.md` · `.claude/skills/code-conventions` · `.claude/skills/security-invariants`.

## 결론 먼저

- **일이 아닌 것을 담을 칸 셋을 만든다 : `대화` · `도구실행` · `잡무`.** 이 셋은 `stats`·`estimate` 기본 표에서 빠지고 `--all` 로만 보인다. **`estimate` 의 p50 표본에서도 빠진다.**
- **`origin` 이 `task-notification`·`peer` 인 작업은 같은 세션 직전에 분류된 작업의 분류를 물려받는다** (`ClassBy="이어받기"`). 앞이 없으면 미분류.
- **분류는 이제 작업 하나만 봐서는 못 정한다.** 세션 단위 진입점 `Rules.ClassifySession([]Task)` 를 새로 두고 `scan` 이 그것만 부른다.
- **도구 호출 이름을 캐시에 넣는다** (`Task.Tools map[string]int`). 캐시 판을 `1`→`2` 로 올리고 **판이 다르면 묻지 않고 자동 전체 재스캔**한다.
- **`rules.txt` 로 고칠 수 있는 것은 「낱말·집합·목록」뿐이고, 순서와 판정 뼈대는 코드에 박는다.**

기대값(캐시 모의 적용, 전체 1096건) : 미분류 **823건(75%) → 210건(19%)**. 대화 208 · 이어받기 316 · 도구실행 60 · 잡무 29.

## 2. 분류하는 차례 (위가 이긴다)

| 순위 | 이름 | 보는 것 | 판정 | `ClassBy` |
| --- | --- | --- | --- | --- |
| 1 | 알림 이어받기 | `Task.Origin` ∈ {`task-notification`, `peer`} **또는** 제목이 `‹task-notification›` 로 시작 | 같은 세션 직전 **일 칸** 작업의 분류. 없으면 `미분류` | `이어받기` |
| 2 | 도구실행(접두) | 제목이 표 2-2 의 접두 중 하나로 시작 | `도구실행` | `원인` |
| 3 | 서브에이전트 | 지금 그대로 : `desc` 끝말 → `desc` 포함 → `agentType`, 토큰 큰 서브가 이김 | 그 분류 | `끝말`·`낱말`·`에이전트` |
| 4 | 제목 낱말 | 지금 그대로 : 제목 끝말 → 제목 포함 | 그 분류 | `제목` |
| 5 | 잡무 | 제목에 `잡무낱말`(표 2-3) 이 있고 **쓰기 도구가 하나도 없다** | `잡무` | `잡무` |
| 6 | 웹조사 | 도구가 하나 이상 있고 **전부 `웹도구`∪`읽기도구`** 이며 `웹도구`가 하나 이상 | `조사` | `웹조사` |
| 7 | 한 줄 셸 대행 | 도구가 `셸도구` 뿐이고 **호출 합이 2회 이하**, 서브 없음 | `도구실행` | `원인` |
| 8 | 대화 | 도구 호출 0 **그리고** 서브 0 | `대화` | `원인` |
| 9 | 기본 | — | `미분류` | `기본` |

순서를 이렇게 잡은 까닭 :

- **1이 맨 위** — 알림은 제목이 통째로 `‹task-notification›` 이라 낱말 규칙이 절대 못 잡는다. 그리고 알림이 벽시계 29시간을 들고 있어 제자리로 보내는 값이 가장 크다.
- **3·4(기존 규칙)를 5~8보다 위에 둔다** — 「문서 고쳐줘」처럼 낱말이 분명한 일은 도구를 안 썼어도 `문서` 로 잡혀야 한다. 대화 판정이 일을 잡아먹지 않게 한다.
- **5의 「쓰기 도구 없음」 조건** — 「커밋 전에 이것도 고쳐줘」처럼 실제로 파일을 고친 것은 잡무가 아니다.
- **7의 2회 이하** — 「`mem index` 돌려 줘」는 셸 한두 번이다. 세 번 넘게 두드렸으면 뭔가를 한 것이라 미분류로 남긴다(사람이 볼 몫).

### 2-1. 도구 이름 집합 (`rules.txt` 로 고칠 수 있다)

| 집합 | 기본값 |
| --- | --- |
| `쓰기도구` | `Write` `Edit` `NotebookEdit` `Artifact` |
| `웹도구` | `WebSearch` `WebFetch` |
| `읽기도구` | `Read` `Grep` `Glob` `ToolSearch` |
| `셸도구` | `Bash` `PowerShell` |

`Agent` · `Skill` · `SendMessage` 는 어느 집합에도 안 넣는다 — 있으면 6·7·8 조건이 저절로 깨져 미분류로 내려간다. **서브를 띄운 작업은 3번에서 이미 판가름 나야 정상**이고, 거기서 못 잡혔으면 사람이 볼 것이다.

### 2-2. 도구실행 접두 (`rules.txt` 로 고칠 수 있다)

| 접두 | 무엇 |
| --- | --- |
| `‹bash-input›` | `!` 로 사용자가 직접 돌린 명령 |
| `‹command-message›` | 슬래시 명령 |
| `‹local-command-caveat›` | 슬래시 명령이 남기는 안내 줄 |
| `## Context Usage` | `/context` 결과 |
| `/` | `/compact` 등 (한 글자 `/` 로 시작하는 제목) |
| `[1 prior /loop wakeup` … | `/loop` 깨우기 — **접두가 아니라 「제목에 `loop wakeup` 을 담음」으로 본다** |

- 살균(`secret.Sanitize`)이 `<` 를 `‹` 로 접기 때문에 **캐시에 남은 제목은 `‹` 꼴**이다. 규칙도 `‹` 로 적는다. 원본 `<` 꼴도 같이 봐 준다(살균 전 값이 들어오는 길은 없지만 방어).
- `/loop` 만 「포함」이고 나머지는 「시작」이다. 이 차이를 `rules.txt` 문법에서 종류 낱말로 가른다(3-2).

### 2-3. 잡무 낱말 (`rules.txt` 로 고칠 수 있다)

`커밋` · `푸시` · `commit` · `push` · `stash` · `머지` · `merge` · `rebase`

## 3. 구조·시그니처

### 3-1. `internal/classify`

```go
// classify.go — 규칙 이름에 넷을 더한다
const (
	BySuffix    = "끝말"
	ByWord      = "낱말"
	ByAgentType = "에이전트"
	ByTitle     = "제목"
	ByOrigin    = "원인"      // 도구실행·대화
	ByInherit   = "이어받기"  // 알림이 앞 작업에서 물려받음
	ByWeb       = "웹조사"
	ByChore     = "잡무"
	ByDefault   = "기본"
)

// Ctx 는 작업 하나 바깥의 사정이다. 지금은 「같은 세션 직전 일 칸 분류」 하나뿐이다.
type Ctx struct {
	Prev model.Class // 없으면 ""
}

// TaskWith 는 작업 하나를 분류한다. 표 2 의 아홉 순위를 그대로 탄다.
func (r *Rules) TaskWith(t *model.Task, ctx Ctx) (model.Class, string)

// Task 는 옛 호출자를 위해 남긴다. TaskWith(t, Ctx{}) 와 같다.
func (r *Rules) Task(t *model.Task) (model.Class, string)
```

```go
// session.go (새 파일)
// ClassifySession 은 한 세션의 작업을 시각 차례로 분류한다.
// 이어받기가 앞 작업을 보므로 작업 하나만으로는 못 정한다 — scan 은 이 함수만 부른다.
func (r *Rules) ClassifySession(tasks []model.Task)
```

`ClassifySession` 의 몸통 (열 줄 안쪽) :

```go
func (r *Rules) ClassifySession(tasks []model.Task) {
	sort.SliceStable(tasks, func(i, j int) bool { return tasks[i].Start.Before(tasks[j].Start) })
	var prev model.Class
	for i := range tasks {
		c, by := r.TaskWith(&tasks[i], Ctx{Prev: prev})
		tasks[i].Class, tasks[i].ClassBy = c, by
		if c.IsWork() && by != ByInherit {
			prev = c // 이어받기끼리 사슬로 번지지 않게 원본만 물려준다
		}
	}
}
```

- **이어받기는 사슬을 안 만든다.** 이어받은 값이 다시 다음 알림에 물려지면 세션 끝까지 한 분류로 물든다. 실제로는 그 사이에 새 사람 요청이 들어와 갱신되므로, 원본 분류만 `prev` 로 남긴다.
- `Start` 가 같은 작업은 안정 정렬로 파일 차례를 지킨다.

### 3-2. `Rules` 에 붙는 칸과 `rules.txt` 문법

```go
type Rules struct {
	Words     map[string]model.Class
	WordOrder []string
	Agents    map[string]model.Class
	Sizes     map[string]float64
	Seeds     map[model.Class]Seed
	Human     map[model.Class]float64
	MinSample int
	BlendMax  int

	// 새로 붙는 것
	ToolSets  map[string]map[string]bool // "쓰기"·"웹"·"읽기"·"셸" → 도구 이름 집합
	Prefixes  []string                   // 도구실행 제두 (시작 비교)
	Contains  []string                   // 도구실행 포함낱말 (loop wakeup 등)
	ChoreWord []string                   // 잡무 낱말
	ShellMax  int                        // 규칙 7 의 셸 호출 상한 (기본 2)
}
```

`rules.txt` 에 종류 다섯을 더한다. 문법은 그대로 **탭 구분·`#` 주석**이다 (TOML 안 들인다).

```
tool	쓰기	Write            # 도구 집합에 이름 하나를 넣는다
tool	웹	WebSearch
tool	읽기	Read
tool	셸	Bash
runpre	‹bash-input›             # 도구실행 접두
runin	loop wakeup              # 도구실행 포함낱말
chore	커밋                     # 잡무 낱말
shell	max	2                # 규칙 7 상한
```

- `tool` 의 집합 이름은 **`쓰기`·`웹`·`읽기`·`셸` 넷뿐**이고, 그 밖이면 줄 번호와 함께 즉시 실패한다(security 7, 지금 `applyRuleLine` 과 같은 태도).
- `runpre`·`runin`·`chore` 는 칸이 둘(종류+값)이라 **지금 `applyRuleLine` 의 「세 칸 이상」 검사에 걸린다.** 검사를 종류별 최소 칸수 표로 바꾼다 :

```go
// rules.go
var minFields = map[string]int{
	"word": 3, "agent": 3, "size": 3, "seed": 5, "human": 3,
	"min": 3, "blend": 3, "tool": 3, "shell": 3,
	"runpre": 2, "runin": 2, "chore": 2,
}
```

### 3-3. 사람이 고칠 수 있는 것과 없는 것

| 고칠 수 있다 (`rules.txt`) | 코드에 박는다 |
| --- | --- |
| 분류 낱말(`word`) · 에이전트 표(`agent`) | **아홉 순위의 차례** |
| 도구 집합 네 개의 원소(`tool`) | 집합 **이름** 넷 |
| 도구실행 접두·포함낱말(`runpre`·`runin`) | `origin` 값(`task-notification`·`peer`) 판정 |
| 잡무 낱말(`chore`) | 이어받기 동작(사슬 금지 포함) |
| 셸 상한(`shell max`) | 「일 칸 / 일 아닌 칸」 나누기(`IsWork`) |
| 시드·배율·표본 경계 | 새 칸 셋의 이름 |

경계를 이렇게 그은 까닭 : **순서를 데이터로 빼면 사용자가 규칙을 뒤섞어 「대화가 일을 잡아먹는」 조합을 만들 수 있다.** 낱말은 틀려도 한 칸이 어긋날 뿐이지만 순서는 표 전체를 망친다.

## 4. 도구 신호와 캐시 판 올리기

### 4-1. 모으기

```go
// internal/model/model.go — Task 에 한 칸
Tools map[string]int `json:"tools,omitempty"` // 메인 세션 도구 이름 → 호출 수

// 도우미 (nil 맵에도 안전하다)
func (t *Task) ToolCalls() int                    // 값 합
func (t *Task) ToolsIn(set map[string]bool) int   // 그 집합에 든 호출 수
func (t *Task) ToolsOut(sets ...map[string]bool) int // 어느 집합에도 없는 호출 수
```

```go
// internal/jsonl/line.go — Line 에 하나
// ToolNames 는 assistant 줄 message.content 의 tool_use 블록 이름을 뽑는다.
func (l *Line) ToolNames() []string
```

- `content` 는 이미 `json.RawMessage` 라 **블록 배열을 한 번 더 풀어** `type=="tool_use"` 인 것의 `name` 만 가져온다. `input` 은 **읽지 않는다** — 명령줄·파일 경로에 비밀정보가 섞이므로 애초에 안 만진다(security 2, 조사 4절에서 경로를 봤지만 그건 조사 스크립트 몫이고 툴은 이름만 센다).
- 넣는 자리는 `collect/session.go` 의 `applyLine` 안 `line.Type == "assistant"` 갈래 한 곳뿐이다.
- **서브에이전트 파일(`readSubagents`)의 도구는 안 센다.** 규칙 6~8 은 「메인 세션이 직접 뭘 했나」를 보는 것이고, 서브가 있으면 3번에서 이미 갈린다.
- 이름은 살균 대상이 아니다(우리가 아는 도구 이름 목록이라 자유 글이 아니다). 다만 **48자를 넘거나 제어문자가 든 이름은 버린다** — 남이 만든 MCP 도구 이름이 표를 깨지 않게.

### 4-2. 판 올리기 — 자동 재스캔으로 한다

```go
// internal/store/scanstate.go
const SchemaVersion = "2" // 1 → 2 : Task.Tools 추가
```

지금 `LoadScanState` 는 판이 다르면 빈 상태를 돌려주므로 **파일은 전부 다시 읽는다.** 그런데 `loadOld` 가 옛 `tasks.jsonl` 을 그대로 들고 오므로 **다시 안 읽힌 프로젝트의 옛 작업이 `Tools` 없이 남는다.** 그래서 :

```go
// cmd/effort/cmd_scan.go
// 판이 다르면 rebuild 와 똑같이 다룬다. 옛 판 작업이 Tools 없이 섞이면 분류가 조용히 틀린다.
stale := st.LoadScanState().Schema != store.SchemaVersion   // LoadScanState 가 판을 지우기 전에 본다
full := *rebuild || stale
```

- `LoadScanState` 는 판이 다를 때 **`NewScanState()` 대신 `Schema` 를 옛 값 그대로 담은 빈 상태**를 돌려주도록 고친다. 판 비교를 호출자가 할 수 있어야 한다.

```go
// 고친 뒤 시그니처는 그대로, 뜻만 또렷해진다
func (s *Store) LoadScanState() *ScanState // 판이 다르면 Files 는 비고 Schema 는 파일에 적힌 옛 값이다
```

- **묻지 않고 자동 재스캔**한다. 근거 : (1) 캐시는 지워도 되는 파생물이라고 이미 정했다(설계 3-3), (2) 안내만 하고 옛 캐시를 그대로 읽으면 `stats` 가 **틀린 값을 아무 표시 없이** 내놓는다 — 조용한 오답이 재스캔 1분보다 나쁘다, (3) 전체 재스캔은 실측에서 세션 101개 · 줄 25425개에 몇 초였다.
- 대신 **한 줄 알린다** : `캐시 판이 1 → 2 로 바뀌어 전부 다시 읽습니다.` (`--quiet` 여도 찍는다. 시간이 왜 걸리는지 사람이 알아야 한다)

### 4-3. `--titles=false` 순서 뒤집기 (지금 있는 결함)

`cmd_scan.go` 는 **제목을 지운 뒤에 분류**한다. 지금도 순위 4(제목 낱말)를 죽이고 있고, 새 규칙 2(도구실행 접두)까지 죽는다.

```go
for i := range res.Tasks { ... }        // 지금 : 제목 지우기 → rules.Task
rules.ClassifySession(res.Tasks)        // 바꾼 뒤 : 분류 먼저
if !keepTitles {                        //          그다음 제목 지우기
	for i := range res.Tasks { res.Tasks[i].Title = "" }
}
```

## 5. 출력에 보이는 것

- `stats` 머리말을 고친다 :
  `작업 1096건 · 미분류 19% · 서브기록없음 15% · 일 아닌 것 297건 뺌(--all)`
  **미분류 %는 「보여준 작업」 기준**이다(일 아닌 것을 뺀 뒤). 분모가 뭔지 헷갈리지 않게 `뺌` 건수를 같은 줄에 적는다.
- `list` · `show` 의 `분류` 칸에 `ClassBy` 가 `이어받기` 면 **`구현←`** 처럼 화살표를 붙인다. 물려받은 값이라는 것을 표에서 바로 보이게 한다.
- `rules` 명령은 새 종류 다섯을 그대로 찍는다(집합·접두·잡무낱말·셸 상한).

## 8. 못 정한 것 · 남는 위험

- **이어받기가 시간을 부풀리는지.** 알림 작업의 벽시계에는 사람이 다음 지시를 내리기까지 기다린 시간이 섞인다(함정 7-9와 같은 뿌리). 지금은 `--metric pure` 로 피할 수 있게만 두고, 실측 뒤 「알림은 순수시간만 센다」로 바꿀지 정한다.
- **한 세션에서 갈래를 여럿 돌릴 때** 알림이 마지막 분류 쪽으로 쏠린다. `toolUseId` 로 알림과 서브를 짝지으면 정확해지지만 실물에서 알림 줄에 그 값이 있는지 못 봤다. 다음 조사 몫.
- **`대화` 로 빠진 작업 중 진짜 일이 얼마나 되는지.** 조사 표본으로는 거의 없었지만 수치로 안 쟀다. `stats --class 대화 --all` 로 사람이 훑을 수 있게만 열어 둔다.
- 크기 배율 `S/M/L/XL` 은 이번에도 안 건드린다. 실측 표본이 늘어난 뒤 다시 잡는다.
