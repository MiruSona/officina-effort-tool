# EffortTool 2차 개선 설계 — 벽시계 바로잡기 · 소단계 묶기 · 되먹임

> 2026-09-01. 근거는 조사(`Docs/Research/2026-09-01-남은작업조사.md`)와 이 설계에서 새로 잰 실물 여덟 세션.
> 앞 설계 두 편(`2026-08-31-공수측정설계.md` · `2026-08-31-분류규칙개선설계.md`)을 **덮지 않고**, 공수측정설계 3·5절과 분류규칙개선설계 2절만 갈아 끼운다.
> 규칙 : `AGENTS.md` · `code-conventions` · `security-invariants`.

## 결론 먼저

- **벽시계의 뜻을 바꾼다.** 작업 시간은 이제 「본줄 구간 ∪ 서브에이전트 구간」의 **합집합 길이**다. 곁줄(큐·파일이력·자리표시·자리비움요약)은 시간을 못 늘린다. 전체 83.2h → 27h 언저리로 줄어든다.
- **본줄을 허용 목록으로 박는다.** 조사가 권한 「빼는 목록」 대신 「넣는 목록」을 쓴다 — 실물에서 조사 목록에 없던 곁줄(`system/away_summary`, 앞줄과 3분 이상 떨어져 찍히는 자리비움 표시)을 하나 더 찾았기 때문이다. 모르는 줄 종류는 `scan` 이 건수와 함께 찍는다.
- **순수시간은 벽시계를 못 넘는다**는 불변식을 넣는다. 넘으면 잘라 내고 `순수시간잘림` 표시를 남긴다. 배경 갈래 수명 135분이 한 작업에 통째로 붙던 것이 여기서 막힌다.
- **소단계 정본은 사람이 정한다.** `%USERPROFILE%\.effort\groups.txt` 를 `rules.txt` 와 나란한 두 번째 정본으로 둔다. 정본이 없는 자리만 자동 묶기(세션 안 · 간격 30분 컷)로 채운다.
- **`estimate` 의 표본 단위를 「작업」에서 「묶음」으로 옮긴다**(`--unit group` 이 기본). 눈금이 10배 어긋나던 것을 여기서 고친다. 대신 **시드와 크기 배율은 전부 다시 잰다.**
- 알림은 **본문 `<task-id>` 로 서브에이전트와 정확히 짝짓는다**(444건 중 390건). 짝이 없고 `<tool-use-id>` 도 없는 54건은 Monitor 감시 신호라 `도구실행` 으로 보낸다.
- 미분류 87건은 **`앞말이어짐` 규칙**(typed · 10분 · 끊는낱말 없음 · 글머리 낱말 있음)으로 50건대까지 내린다.
- 캐시 판을 **2 → 3** 으로 올린다(자동 전면 재스캔). 명령 둘(`group` · `actual`)이 는다.

## 0. 이 설계에서 새로 잰 것 (결정 1의 근거)

실물 세션 여덟 개(가장 큰 것들)에서 **줄 종류별 「앞줄과의 간격」** 을 쟀다. 곁줄인지 아닌지는 이 값 하나로 갈린다 — 사람을 기다린 뒤에 찍히는 줄은 간격이 크다.

```go
		}
	}
	if ctx.Prev == "" { return model.ClassUnknown, ByInherit }
	return ctx.Prev, ByInherit
}
```

### 4-2. 판정

```go
// internal/classify/classify.go — byTools 뒤에 붙는다
func (r *Rules) TaskWith(t *model.Task, ctx Ctx) (model.Class, string) {
	...
	c, by := r.byTools(t, title)
	if by == ByDefault {
		if cc, ok := r.contInherit(t, title, ctx); ok {
			return cc, ByContinue
		}
	}
	return c, by
}

// contInherit 는 사람이 앞말을 이어 말한 것인지 본다. 네 조건을 다 채워야 한다.
func (r *Rules) contInherit(t *model.Task, title string, ctx Ctx) (model.Class, bool) {
	if ctx.Prev == "" || !ctx.Prev.IsWork() { return "", false }            // ① 물려받을 앞 일 칸
	if t.PromptSource != model.SourceTyped { return "", false }             // ② 사람이 직접 친 것
	if !r.hasContFirst(title) { return "", false }                          // ③ 글머리 낱말
	if r.hasContStop(title) || r.isChore(title) { return "", false }        // ④ 끊는 낱말·잡무 낱말
	if ctx.PrevEnd.IsZero() || t.Start.IsZero() || t.Start.Before(ctx.PrevEnd) { return "", false }
	if t.Start.Sub(ctx.PrevEnd) > time.Duration(r.ContMax)*time.Minute { return "", false } // ⑤ 10분
	return ctx.Prev, true
}

func (r *Rules) hasContFirst(title string) bool // 글머리(HasPrefix) 비교
func (r *Rules) hasContStop(title string) bool  // 포함(Contains) 비교
```

- **잡무 낱말이 있으면 이어짐을 막기만 하고 분류는 안 바꾼다.** 「좋아 그러면 다 커밋하고 푸시해줘」(쓰기 도구 47회)를 잡무로 보내려면 순위 7의 「쓰기 도구 없음」 조건을 풀어야 하는데, 그러면 「커밋 전에 이것도 고쳐줘」가 잡무로 샌다. **일 칸으로 잘못 새는 것보다 미분류로 남아 사람이 보는 게 낫다.** 이 탓에 잡히는 건수는 조사 어림(35건)보다 3~5건 적어진다.
- `PrevEnd` 는 **작업마다 갱신**하고 `Prev`(분류)는 원본만 물려준다.

```go
// internal/classify/session.go
func (r *Rules) ClassifySession(tasks []model.Task) {
	sort.SliceStable(tasks, func(i, j int) bool { return tasks[i].Start.Before(tasks[j].Start) })
	idx := agentIndex(tasks)
	var prev model.Class
	var prevEnd time.Time
	for i := range tasks {
		c, by := r.TaskWith(&tasks[i], Ctx{Prev: prev, PrevEnd: prevEnd, Agents: idx})
		tasks[i].Class, tasks[i].ClassBy = c, by
		// 물려받은 값(이어받기·짝짓기·앞말이어짐)은 다시 물려주지 않는다.
		if c.IsWork() && by != ByInherit && by != ByMatch && by != ByContinue {
			prev = c
		}
		prevEnd = tasks[i].End // 시각 창은 바로 앞 작업 기준이다
	}
}
```

`classLabel`(공용) : `앞말이어짐`·`짝짓기`도 화살표를 붙인다 — `구현←`.


- 숫자 글머리는 `1.`·`2.`·`3.` 셋만 기본. 「2까지」 같은 꼴은 사람이 `contfirst 2까지` 를 늘린다.
- `cont max`·`gap max` 는 `shell max` 와 같은 꼴이라 `setNamedInt` 를 그대로 쓴다.
- `rules --check` · `rules` 출력의 「쓰임/값」 표에 네 줄이 는다 : `이어짐 글머리` · `이어짐 끊는말` · `이어짐 상한` · `묶기 간격`.

## 8. 캐시 스키마 변경과 판 번호

```go
// internal/store/scanstate.go
// 1 → 2 : Task.Tools 추가. 2 → 3 : 벽시계 뜻 바뀜(구간 합집합) · promptSource · 알림 task-id · parentAgentId.
const SchemaVersion = "3"
```

`model.Task` 에 느는 칸 (전부 `omitempty` 로 캐시 크기를 안 불린다) :

| 칸 | 꼴 | 무엇 |
| --- | --- | --- |
| `PromptSource` | `prompt_source,omitempty` | `typed`·`system`·`queued`·`sdk`·`suggestion_accepted`·`기타` |
| `NotifyTaskID` | `notify_task_id,omitempty` | 알림 본문 `<task-id>` |
| `NotifyKind` | `notify_kind,omitempty` | `agent` \| `monitor` |

| `AgentWallMs` | `agent_wall_ms` | 서브 구간 합집합 |
| `WallMs` | `wall_ms` | **뜻이 바뀐다** : 본줄 ∪ 서브 합집합 |

`model.Agent` : `ParentAgentID string` (`parent_agent_id,omitempty`)

`Warn` 값 : `순수시간과다` 가 사라지고 `순수시간잘림` · `배경갈래` 가 는다.

## 10. 재측정 계획

고친 뒤 이 차례대로 밟는다. 어느 한 칸이 기대 범위 밖이면 다음으로 안 넘어간다.

### 10-1. 재스캔과 시간 검산

```powershell
.\EffortTool\bin\effort.exe scan --all          # 판 2→3 이라 저절로 전면 재스캔
.\EffortTool\bin\effort.exe stats --by class --all
```

| --- | --- | --- | --- |
| 벽시계 합 | 83.2h | **25~33h** | 본줄 목록부터 다시 본다. `모르는 줄 종류` 줄을 먼저 읽는다 |
| `도구실행` | 10.2h | **9~10h** (거의 안 준다) | 크게 줄면 본줄을 너무 많이 뺀 것이다 |
| `잡무` | 0.7h | **0.6~0.7h** | 위와 같다 |
| `조사` | 31.5h | 6~9h (서브 구간 합집합만큼 6.2h 보다 크다) | — |

### 10-2. 분류 검산

| 칸 | 지금 | **기대** |
| --- | --- | --- |

`앞말이어짐` 이 40건을 넘으면 글머리 낱말이 너무 넓은 것이니 잡힌 것을 눈으로 훑는다.

### 10-3. 크기 배율 다시 잡기

묶음 단위로 옮겼으니 지난번 값(0.3/1.0/2.4/5.0)은 무효다. 지난번과 같은 방법을 묶음에 그대로 쓴다.

```powershell
.\EffortTool\bin\effort.exe list --group gap:30m --limit 0 --json
```

1. 일 칸 묶음의 벽시계 분위수 `p20 · p50 · p80 · p95` 를 뽑는다.
2. `S = p20/p50` · `M = 1.0` · `L = p80/p50` · `XL = p95/p50`, 소수 둘째 자리에서 반올림.
3. `rules.txt` 의 `size` 네 줄을 손으로 고친다.

### 10-4. 시드 다시 잡기

1. 묶음 단위 · 분류별로 `p50 · p20 · p80` 을 분으로 뽑는다.
2. **표본이 12건(`blend sample`) 이상인 분류만** `seed` 줄을 새 값으로 바꾼다. 그 아래는 지금 시드를 그대로 둔다.
3. `설계`·`실측`·`검토` 는 이어받기를 뺀 표본이 얇으므로 대개 안 바뀐다.

### 10-5. 사람 눈금 배율(`human`)

**이번엔 안 건드린다.** `effort actual` 로 한두 회차를 실제로 돌려 배율 열이 쌓인 뒤에 고친다.

### 10-6. 남기기

- mem : 벽시계 뜻 바꿈 · 새 배율 · 새 시드 (decision), 밟은 함정 (caution). scope efforttool.
- 새 값을 `Docs/Todo/진행상황.md` 「이미 정한 것」 표와 `effort-usage` 스킬에 같이 옮긴다.

## 12. 닫는 미결 · 남는 위험

**닫는다** (조사에서 실물로 확인됨) :
- compaction — 8건 전부 manual, 파서 안 깨짐, 검산 무관. 문제 없음으로 닫는다.
- `spawnDepth ≥ 2` — depth 2 = 34건 · 3 = 3건, 이미 다 읽힌다. `show` 표시만(소단계 12).
- 알림 짝짓기 — 열쇠는 본문 `<task-id>`, 444/444 (소단계 5).
- 여러 기계 — 합치지 않는다 (mem `20260901-9a66e5bf`, 사용자 확정).

**남는 위험** :
- 묶음 단위로 옮긴 뒤에도 눈금이 안 맞을 수 있다 → 다음 회차에 `gap max` 60분으로 올려 재측정. 컷 값을 rules.txt 로 연 까닭.
- `앞말이어짐` 오답은 사람이 훑는 것 말고 못 센다 → `class_by` 로 골라 볼 수 있게 함.
- `groups.txt` 는 소급 적용 안 된다 — 지난 기록 묶음은 전부 자동, `actual` 은 오늘 이후부터 쓸모.
- JSONL 합 < cost-state 까닭은 이번에도 안 밝힌다 (나란히 보여주기 그대로).
- rules.txt 변경을 scan 이 못 알아채는 것(todo `20260901-0178158e`)은 범위 밖. `group --add` 는 캐시를 안 건드리고 읽을 때마다 정본을 다시 읽는다.
