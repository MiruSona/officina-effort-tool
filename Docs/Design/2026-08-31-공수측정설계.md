# 공수 측정 툴(EffortTool) 설계

> 2026-08-31. 근거는 `EffortTool/Docs/Research/2026-08-31-공수측정조사.md` (아래 「조사 고침」 절에 실물로 확인한 정정 두 건이 있다).
> 규칙 : `AGENTS.md` · `.claude/skills/code-conventions` · `.claude/skills/security-invariants`.

## 결론 먼저

- **Go 1.26 단일 exe `effort.exe`. 바깥 라이브러리 0개(표준 라이브러리만), `CGO_ENABLED=0`.**
- **명령 여섯 : `scan` · `stats` · `estimate` · `show` · `list` · `rules`** (+ `version` `help`). 데몬·상주 프로세스 없음, LLM 호출 0.
- **작업 한 건 = `promptId` 한 개.** 서브에이전트 파일 줄도 같은 `promptId` 를 들고 있어 부모 작업에 자동으로 붙는다.
- **파생 저장소는 `%USERPROFILE%\.effort\`** (`EFFORT_HOME` 또는 `--home` 으로 옮김). 원본 JSONL 은 **열기 전용**, `.effort` 아래는 **지워도 `effort scan --rebuild` 로 되살아나는 파생물**이다 (고정 기억 20260822-71e604f3 과 같은 원칙).
- **예상 공수 = 분류별 과거 실측의 p50 × 크기 배율**, 범위는 p20~p80. 표본이 5건 미만이면 `공수기록.md` 의 사람 눈금 배율을 시드로 쓰고, 5~12건이면 섞는다.
- 출력은 **한국어 파이프 표** — 그대로 `Docs/History/공수기록.md` 에 붙는다.

## 0. 조사 고침 (실물로 확인)

조사 문서 1절의 두 줄을 고친다. 구현이 여기서 갈린다.

| 조사 문서가 적은 것 | 실물 | 설계에서 하는 일 |
| --- | --- | --- |
| "한 요청에서 파생된 **모든 줄**이 같은 `promptId` 를 공유한다" | **`promptId` 는 `user` 줄에만 있다.** `assistant` · `system:turn_duration` · `attachment` 에는 없다 (한 세션 전수 확인 : user 15/15, assistant 0/23, turn_duration 0/3) | **파일을 순서대로 읽으며 「마지막으로 본 promptId」를 이어 붙인다**(carry-forward). `parentUuid` 사슬은 보조 검산용 |
| `cost-state` 는 세션당 1~2회 | 맞다. **진행 중 세션에는 없다** | 없으면 그 세션을 `진행중` 으로 표시하고 검산 칸을 `—` 로 둔다 |

확인한 것 : 서브에이전트 파일의 `user` 줄 `promptId` 는 **부모 메인 파일의 promptId 와 같다** (두 에이전트 모두 1/1 일치). 부모-자식 잇기는 `toolUseId` 없이도 된다.

## 2. CLI — 명령 여섯

```
effort scan     [--home DIR] [--projects DIR] [--project NAME|--all] [--rebuild] [--titles] [--quiet]
effort stats    [--class C] [--since YYYY-MM-DD] [--by class|agent|model|session] [--md|--wide|--json]
effort estimate [소단계...] [--from FILE|-] [--human] [--metric wall|pure] [--md|--wide|--json]
effort show     <promptId|접두사>  [--json]
effort list     [--class C] [--since D] [--session ID] [--limit N] [--sort wall|pure|tok]
effort rules    [--check]
effort version | effort help [명령]
```

| 명령 | 하는 일 | 읽는 것 / 쓰는 것 |
| --- | --- | --- |
| `scan` | JSONL 을 훑어 작업 레코드를 만들고 캐시에 넣는다. 기본은 **바뀐 파일만**(증분), `--rebuild` 는 통째로 | 읽기 `~/.claude/projects/**` · 쓰기 `.effort/cache/*` |
| `stats` | 분류·에이전트·모델·세션별 건수 · 벽시계 · 순수시간 · 토큰 · **토큰당 시간(ms/1K tok)** | 읽기 캐시만 |
| `estimate` | 소단계 목록을 받아 `\| 소단계 \| 예상 \| 범위 \|` 표를 낸다 | 읽기 캐시 + `rules.txt` |
| `show` | 작업 하나 상세 (서브에이전트 목록 · 모델별 토큰 · 검산) | 읽기 캐시만 |
| `list` | 작업 목록 한 줄씩 | 읽기 캐시만 |
| `rules` | 분류 규칙·크기 배율·시드 값을 보여준다. `--check` 는 문법 검사 | 읽기 `rules.txt` |

- **`stats` · `estimate` · `show` · `list` 는 절대 쓰기를 안 한다.** 캐시가 없으면 "먼저 `effort scan` 을 돌리세요" 라고 말하고 종료 2.
- 상주 프로세스·데몬·워처 없음 (mem 결정 20260822-ed9614cf 와 같은 줄).
- 옵션은 **모르는 것이 오면 즉시 실패**한다 (security 7). 조용히 넘기지 않는다.

## 3. 데이터 모델

### 3-1. 구조체

```go
// internal/model/model.go
type Usage struct {
	Input       int64 `json:"in"`
	Output      int64 `json:"out"`
	CacheRead   int64 `json:"cr"`
	CacheCreate int64 `json:"cc"`
	Thinking    int64 `json:"th"`
}

func (u Usage) Total() int64      // Input+Output+CacheRead+CacheCreate  (Thinking 은 Output 안쪽이라 안 더한다)
func (u Usage) Billable() int64   // Input+Output+CacheCreate  (cache read 제외 — 값싼 토큰)
func (u *Usage) Add(o Usage)

type ModelUsage map[string]Usage // 열쇠는 정규화된 모델 이름 (7-4)

type Class string // "조사" "설계" "구현" "실측" "문서" "검토" "미분류"

type Agent struct {
	AgentID     string     `json:"agent_id"`
	AgentType   string     `json:"agent_type"`   // Explore / Plan / general-purpose / …
	Description string     `json:"desc"`         // 살균 뒤 저장 (6-3)
	Model       string     `json:"model"`        // meta.json 의 opus/sonnet
	SpawnDepth  int        `json:"depth"`
	ToolUseID   string     `json:"tool_use_id"`
	Start       time.Time  `json:"start"`
	End         time.Time  `json:"end"`
	Usage       ModelUsage `json:"usage"`
	Turns       int        `json:"turns"`        // 중복 제거 뒤 assistant 줄 수
	Class       Class      `json:"class"`
	MetaMissing bool       `json:"meta_missing"` // meta.json 이 없다 (옛 버전)
}

type Task struct {
	PromptID  string     `json:"prompt_id"`
	SessionID string     `json:"session_id"`
	Project   string     `json:"project"`   // cwd 절대경로
	Title     string     `json:"title"`     // 첫 user 텍스트 60자, 살균+비밀검사 (6-2)
	Start     time.Time  `json:"start"`
	End       time.Time  `json:"end"`
	WallMs    int64      `json:"wall_ms"`   // End-Start
	PureMs    int64      `json:"pure_ms"`   // turn_duration.durationMs 합
	Usage     ModelUsage `json:"usage"`     // 메인 + 서브에이전트 전부
	MainUsage ModelUsage `json:"main_usage"`
	Agents    []Agent    `json:"agents"`
	Turns     int        `json:"turns"`
	Class     Class      `json:"class"`
	ClassBy   string     `json:"class_by"`  // "끝말" | "에이전트" | "제목" | "기본"
	Version   string     `json:"version"`   // Claude Code 판
	Origin    string     `json:"origin"`    // human / 그 밖
	Warn      []string   `json:"warn"`      // "turn_duration 없음" 같은 표시
}

type Session struct {
	SessionID   string     `json:"session_id"`
	Project     string     `json:"project"`
	Title       string     `json:"title"`       // ai-title 줄, 살균
	Start       time.Time  `json:"start"`
	End         time.Time  `json:"end"`
	CostUSD     float64    `json:"cost_usd"`
	TotalMs     int64      `json:"total_ms"`    // cost-state.totalDuration
	APIMs       int64      `json:"api_ms"`      // totalAPIDuration
	ToolMs      int64      `json:"tool_ms"`     // totalToolDuration
	StateUsage  ModelUsage `json:"state_usage"` // cost-state.modelUsage — 정답값
	SumUsage    ModelUsage `json:"sum_usage"`   // 작업 합 (JSONL)
	CoverPct    float64    `json:"cover_pct"`   // SumUsage.Total / StateUsage.Total × 100
	InProgress  bool       `json:"in_progress"` // cost-state 줄이 없다
	TaskCount   int        `json:"task_count"`
}
```

### 3-2. 중복 제거 규칙 (조사 2절 · mem 20260831-4dcdb496)

```go
// internal/collect/dedup.go
type usageKey struct{ RequestID, MessageID string }

type Dedup struct {
	last map[usageKey]Usage // 마지막에 본 값
	max  map[usageKey]int64 // 본 output_tokens 최대값
	Rollback int            // last < max 인 횟수 — 정직하게 보고한다
}

func (d *Dedup) Put(k usageKey, u Usage)
func (d *Dedup) Sum() Usage
```

- 열쇠는 `(requestId, message.id)`. **last-wins** — `output_tokens` 는 스트리밍 중 단조 증가하므로 마지막 것이 정답이다.
- `requestId` 가 없는 줄(합성 assistant 등)은 열쇠를 `("", uuid)` 로 둬 절대 안 뭉친다.
- 단조 증가 가정이 깨진 경우(`last < max`)를 `Rollback` 으로 세어 `scan` 끝 줄에 **건수를 찍는다.** 조용히 넘기지 않는다.

### 3-3. 파생 저장소 (지워도 되는 것)

```
%USERPROFILE%\.effort\
  rules.txt              사람이 고치는 분류 규칙·배율·시드   ← 유일한 「원본」
  cache/
    tasks.jsonl          Task 한 건이 한 줄 (NDJSON)
    sessions.jsonl       Session 한 건이 한 줄
    scanstate.json       파일별 {크기, mtime, 마지막줄오프셋, 판} — 증분 스캔용
    schema                스키마 판 번호 한 줄. 안 맞으면 자동 전체 재스캔
  scan.lock              PID + 프로세스 시작시각
```

- **원본 JSONL 은 `os.Open` 읽기 전용으로만 연다.** 쓰기·이름바꾸기·삭제 코드 경로를 아예 두지 않는다 (security 5).
- `cache/` 는 파생물이다 — 통째로 지우고 `effort scan --rebuild` 하면 같은 값이 나온다. **캐시만 고치는 코드 경로는 없다** (security 8).
- `rules.txt` 만 사람이 고치는 정본이고, 없으면 `scan`·`rules` 가 **내장 기본값으로 처음 한 번 만들어 준다**(있으면 절대 덮어쓰지 않는다).
- 자리 정하는 차례 : `--home` → `EFFORT_HOME` → `%USERPROFILE%\.effort` (리눅스는 `$XDG_DATA_HOME/effort` → `~/.effort`). **프로젝트 폴더 안에 안 만든다** — 툴킷이라 여러 프로젝트를 가로질러 재기 때문이다.

## 4. 분류 규칙

### 4-1. 정하는 차례 (위가 이긴다)

| 순위 | 보는 것 | 규칙 |
| --- | --- | --- |
| 1 | 서브에이전트 `description` **끝말** | 표 4-2 의 낱말로 끝나면 그 분류 |
| 2 | `description` 안에 든 낱말 | 같은 표를 **포함** 으로 다시 본다 (끝말이 안 맞을 때) |
| 3 | `agentType` | `Explore`→조사, `Plan`→설계, `superpowers:code-reviewer`→검토, 그 밖→다음 순위 |
| 4 | 작업 `Title`(사용자 첫 줄) 의 같은 낱말 | 서브에이전트가 아예 없는 작업용 |
| 5 | 기본 | `미분류` |

- **작업(Task)의 분류는 「그 작업 안 서브에이전트 분류 중 토큰을 가장 많이 쓴 것」** 으로 정한다. 서브가 없으면 순위 4·5 로 간다. 같은 작업에 조사와 구현이 섞이면 큰 쪽이 이긴다 — 예상 표가 「무슨 일에 얼마 걸리나」를 재는 것이라 그게 맞다.
- `ClassBy` 에 몇 번 규칙으로 정했는지 남긴다. `stats --by class` 가 **미분류 비율**을 같이 찍어 규칙을 언제 손볼지 알려 준다.

### 4-2. 낱말 표 (`rules.txt` 기본값 — 사용자가 고칠 수 있다)

| 분류 | 끝말·낱말 | 대응 `agentType` |
| --- | --- | --- |
| 조사 | 조사 · 확인 · 알아보기 · 찾기 · 탐색 · 훑기 · research | `Explore` |
| 설계 | 설계 · 계획 · 기획 · 방안 · design · plan | `Plan` |
| 구현 | 구현 · 만들기 · 고침 · 고치기 · 수정 · 추가 · 붙이기 · 코드 · 리팩터 | — |
| 실측 | 실측 · 측정 · 재기 · 벤치 · 성능 · 돌려보기 | — |
| 문서 | 문서 · 정리 · 기록 · 보고 · README · 가이드 · 안내 | — |
| 검토 | 검토 · 리뷰 · 점검 · 감사 · review | `superpowers:code-reviewer` |

`rules.txt` 문법 (탭 구분, `#` 는 주석. TOML 파서를 안 들이려고 일부러 단순하게 뒀다) :

```
# 종류	분류	값
word	조사	조사
word	조사	확인
agent	설계	Plan
size	S	0.6
size	M	1.0
size	L	1.8
size	XL	3.2
seed	조사	10	5	20        # 분류 p50분 p20분 p80분
human	구현	0.25                # 사람 눈금 배율 (공수기록.md)
min	sample	5                   # 이 아래면 시드만 쓴다
blend	sample	12                # 이 위면 실측만 쓴다
```

- 모르는 종류 낱말이 나오면 **줄 번호를 찍고 즉시 실패**한다 (security 7). 조용히 넘기지 않는다.

## 5. 예상 공수 계산식

### 5-1. 뼈대

분류 `c`, 측정 기준 `m`(기본 `wall`, `--metric pure` 로 순수시간) 에 대해

```
표본  S(c) = { t ∈ 캐시 | t.Class == c, t.Start ≥ 오늘-N일(기본 120), t.m > 0 }
p50 = 분위수(S, 0.5),  p20 = 분위수(S, 0.2),  p80 = 분위수(S, 0.8)      // 선형 보간

예상(c, 크기) = p50(c) × 배율(크기)
범위(c, 크기) = [ p20(c) × 배율(크기), p80(c) × 배율(크기) ]
```

- 배율 : `S 0.6 · M 1.0 · L 1.8 · XL 3.2` (`rules.txt`). 크기를 안 적으면 `M`.
- **표본 수 n 에 따른 섞기** (콜드 스타트) :

| n | 쓰는 값 |
| --- | --- |
| n < 5 | **시드만** (`seed` 줄. 출처를 `(시드)` 로 표시) |
| 5 ≤ n < 12 | `w = (n−5)/7` · `예상 = w×실측p50 + (1−w)×시드p50` — 표시 `(섞음 n=7)` |
| n ≥ 12 | **실측만** — 표시 `(실측 n=31)` |

- 시드 기본값 (`Docs/History/공수기록.md` 의 벽시계 실측에서 뽑았다) :

| 분류 | p50 | p20 | p80 | 근거 |
| --- | --- | --- | --- | --- |
| 조사 | 10분 | 5분 | 20분 | "Opus 웹조사 1건 = 벽시계 약 10분" (08-29 기록) |
| 설계 | 20분 | 6분 | 50분 | SoundTool 설계 7·11분 ~ ArtTool 설계 45·55분 |
| 구현 | 20분 | 8분 | 60분 | mem 무효화 소단계 5~25분, SoundTool 구현 17·20분 |
| 실측 | 45분 | 20분 | 180분 | "실측은 AI 라고 안 줄어든다" (08-25 기록) |
| 문서 | 8분 | 3분 | 20분 | 문서 3종 2분 ~ 안내 문서 9분 |
| 검토 | 10분 | 5분 | 25분 | 리뷰 7·15분 |
| 미분류 | 15분 | 5분 | 40분 | — |

- **사람 눈금 모드** `--human` : 소단계마다 사람 눈금(분)을 같이 주면 `예상 = 사람눈금 × human배율(분류)` 로 낸다. 기본 배율은 `Docs/History/공수기록.md` 결론 그대로 **구현 0.25 · 문서 0.5 · 설계 0.7 · 조사 0.7 · 검토 0.5 · 실측 1.0** 이다.
  실측 표본이 12건을 넘으면 `--human` 값과 실측 값을 **두 칸 나란히** 찍어 어느 쪽이 맞았는지 보이게 한다.
- 눈금 규칙 두 줄을 코드로 박는다 (`공수기록.md` 「눈금 규칙」) :
  - 분류가 `실측` 이면 **×2** 를 자동으로 건다 (`--no-x2` 로 끔).
  - `--freeze` 를 주면 **「동결→재측정→고침→재동결」 한 바퀴 더**를 잡아 ×1.5 를 건다.

### 5-2. 입력 — 인자와 stdin 둘 다

```
effort estimate 조사:M 설계:M 구현:L 시험:구현:M
```
- 인자꼴 : `[이름:]분류[:크기]`. 이름을 안 적으면 분류 이름을 그대로 쓴다.

```
effort estimate --from -  <<'EOF'
| 소단계 | 분류 | 크기 | 사람눈금 |
| --- | --- | --- | --- |
| 1. JSONL 파서 | 구현 | M | 60 |
| 2. 분류기 | 구현 | S | 30 |
| 3. 실측·검산 | 실측 | M | |
EOF
```
- stdin/파일꼴 : **`공수기록.md` 와 같은 파이프 표**를 그대로 먹는다. `|---|` 구분선과 머리 줄은 건너뛴다. 열은 이름·분류가 필수, 크기·사람눈금은 선택.
- 인자와 `--from` 을 같이 주면 **사용법 오류(종료 1)** 다. 둘 중 하나만 받는다.

### 5-3. 나오는 표

```
| 소단계 | 분류 | 예상 | 범위 | 근거 |
| --- | --- | --- | --- | --- |
| 1. JSONL 파서 | 구현 | 20분 | 8~60분 | 시드 |
| 2. 분류기 | 구현 | 12분 | 5~36분 | 시드 |
| 3. 실측·검산 | 실측 | 1시간 30분 | 40분~6시간 | 시드 ×2(실측) |
| **합** | | **약 2시간 2분** | **53분~7시간 36분** | |
```

- 합의 범위는 각 칸의 단순 합이다 (분산 합이 아니다 — 사람이 검산할 수 있어야 한다). 그렇게 잡은 이유를 표 아래 한 줄로 적어 준다.

## 6. 출력 형식과 보안

### 6-1. 표와 한글 폭

- 기본은 **파이프 표(`--md`)** — 폭 계산이 필요 없고 `공수기록.md` 에 그대로 붙는다.
- `--wide` 는 화면 정렬 표다. `text/tabwriter` 는 한글에서 어긋나므로 **직접 폭을 센다.**

```go
// internal/render/width.go
func RuneWidth(r rune) int  // 동아시아 W·F = 2, 결합문자·제어 = 0, 그 밖 = 1
func StringWidth(s string) int
func PadRight(s string, w int) string
func Table(head []string, rows [][]string, style Style) string // Style: Pipe | Wide
```
- 폭 표는 유니코드 `EastAsianWidth` 의 W·F 구간만 손으로 적는다(약 20줄). 라이브러리 추가 없음.
- 시간 표기 `internal/render/dur.go` : `func Minutes(ms int64) string` — 60분 미만 `47분`, 이상 `1시간 23분`, 1분 미만 `1분 미만`, 0 은 `—`.
- 토큰 표기 : `12.3K` · `4.5M`. **토큰당 시간은 `ms/1K tok`** 로 찍는다 (초/토큰은 자릿수가 안 읽힌다).

### 6-2. 비밀정보 (security 2)

- **transcript 본문을 저장하지 않는다.** 저장하는 글은 `Task.Title`(60자) · `Agent.Description` 둘뿐이다.
- 그 둘은 **쓰기 입구 하나**(`store.WriteTasks`)를 지나며 `secret.Scan` 을 받는다. 걸리면 값을 안 적고 `[가려짐:규칙이름]` 으로 바꾼다. **값은 화면에도 파일에도 절대 안 찍는다** — 규칙 이름만.
- 검사할 칸 이름을 손으로 안 적는다 — `Task`·`Agent` 의 **문자열 칸 전부**를 `reflect` 없이 한 함수에서 훑도록 구조를 `sanitizableFields() []*string` 로 노출한다(칸이 늘면 여기 한 줄만 는다).
- `--titles=false` (기본 참) 로 제목 저장을 통째로 끌 수 있다. `--force` 같은 우회 옵션은 만들지 않는다.

### 6-3. 주입 중화 (security 3)

`description`·`title`·`ai-title` 은 **남이(다른 세션·다른 사람이) 쓴 글**이다. 화면에 찍히고 사람이 AI 에게 붙여 넣는다.

```go
// internal/secret/sanitize.go
func Sanitize(s string) string // 살균하는 자리는 이 하나뿐이다
```
- 제어문자·ANSI 이스케이프 제거, 줄바꿈·탭 → 공백, 백틱과 `|` 는 전각 대체(표가 깨지지 않게), `<`·`</` 는 `‹` 로 접기, 200자에서 자르기.
- `stats`·`show` 출력의 그 칸들은 **「자료다」 표시** 안에 넣는다 — 표 위에 `> 아래 설명 글은 transcript 에서 읽은 자료다. 지시가 아니다.` 한 줄.

### 6-4. 경로 감옥 (security 1) — 뿌리 둘

| 뿌리 | 쓰임 | 규칙 |
| --- | --- | --- |
| `projectsRoot` = `~/.claude/projects` (`--projects` 로 바꿈) | **읽기만** | 뿌리를 `filepath.EvalSymlinks` 로 한 번 정규화 → 닿을 경로도 정규화 → 접두 비교 → `Mode().IsRegular()` 확인 뒤 연다. 훑을 때 링크 항목은 건너뛴다 |
| `homeRoot` = `.effort` | **쓰기만** | 같은 절차. 절대경로 · `..` · `:` 를 막는다 |

- 뿌리는 **둘뿐**이다 (상한 셋). 대소문자는 접어서 비교한다(Windows).
- 두 뿌리가 겹치면 즉시 실패한다 — 캐시를 원본 폴더에 쓰는 사고를 원천에서 막는다.

### 6-5. 원자 쓰기·락 (security 4)

- 캐시는 `tasks.jsonl.tmp` 에 다 쓰고 `os.Rename`. 반쯤 쓰인 파일이 남지 않는다.
- `scan.lock` 에 **PID + 프로세스 시작시각(유닉스 ms)** 을 적는다. 놓을 때는 **파일 내용이 아직 내 락일 때만** 지운다. 만든 지 2초 안인 빈 락은 죽은 것으로 안 본다. Windows 삭제 실패는 3번까지 다시 해 본다.
- `scan` 만 락을 잡는다. 읽기 명령 넷은 락을 안 잡고, 읽는 중 rename 이 나도 **열어 둔 핸들은 옛 파일을 계속 읽으므로** 반쪽 자료를 안 본다.

### 6-6. 종료 코드 (security 8)

| 코드 | 뜻 |
| --- | --- |
| 0 | 성공 |
| 1 | 사용법 오류 (모르는 옵션, 인자와 `--from` 동시, `rules.txt` 문법 오류) |
| 2 | 낼 것이 없음 (캐시 없음 · 표본 0) — **왜 0건인지 한 줄 말한다** |
| 3 | 읽기 실패 (경로 감옥 위반 · 폴더 없음 · 권한) |
| 4 | 쓰기·락 실패 |
| 5 | 손상 줄 비율이 상한(기본 2%)을 넘음 |

## 7. 함정 대응

| # | 함정 | 대응 |
| --- | --- | --- |
| 7-1 | **스트리밍 중복** (2.7배 뻥튀기) | `(requestId, message.id)` last-wins. `Rollback` 건수를 `scan` 끝에 찍는다 (3-2) |
| 7-2 | **`subagents/` 폴더가 없는 옛 세션** | 폴더가 없으면 메인만 세고 **`Task.Warn` 에 `서브기록없음`** 을 넣는다. `stats` 는 그런 작업 비율을 머리말에 찍는다. 있는 척하지 않는다 |
| 7-3 | **`meta.json` 없는 에이전트 파일** | `Agent.MetaMissing = true`, `AgentType = "미상"`. 분류는 순위 4(제목)로 내려간다 |
| 7-4 | **모델 이름이 다르다** (`claude-opus-5[1m]` vs `claude-opus-5`) | `model.Normalize(s)` — 소문자화 → `[…]` 꼬리 제거 → `-YYYYMMDD` 날짜 꼬리 제거 → 별칭 표(`opus`→`claude-opus-5` 등) 적용. **정규화 자리는 이 함수 하나** |
| 7-5 | **JSONL 합 < `cost-state` (큰 세션 약 45%)** | 배분하지 않는다. `Session.CoverPct` 를 계산해 **나란히** 보여준다: `작업 합 1.2M / 세션 총계 2.2M (55%)`. 60% 미만이면 `stats` 머리말에 `⚠ 쪼갠 합이 세션 총계보다 작습니다(까닭 미확정)` 한 줄. 예상 계산은 **시간**을 쓰지 토큰을 안 쓰므로 이 구멍이 예상값을 흔들지 않는다 |
| 7-6 | **`bufio.Scanner` 64KB 상한** | `sc.Buffer(make([]byte, 0, 256*1024), 8*1024*1024)`. 8MB 를 넘는 줄은 **건너뛰고 세어서** 보고한다 (조용히 안 넘긴다). 손상 줄 비율이 2% 넘으면 종료 5 |
| 7-7 | **진행 중 세션(`cost-state` 없음)** | `Session.InProgress = true`. 검산 칸은 `—`. **마지막 작업(promptId)은 아직 안 끝났을 수 있으므로 `Task.Warn` 에 `진행중`** 을 달고 `estimate` 표본에서 뺀다 |
| 7-8 | **`promptId` 가 user 줄에만 있다** | 파일 순서대로 carry-forward (0절). 첫 `user` 줄 앞의 줄들은 `__preamble` 로 모아 표본에서 뺀다 |
| 7-9 | **사용자 답을 기다린 시간** | 벽시계(`WallMs`)에는 들어가고 순수시간(`PureMs` = `turn_duration` 합)에는 안 들어간다. **`estimate` 기본은 `wall`, 「AI 가 붙잡고 있던 시간」이 필요하면 `--metric pure`.** 두 값을 `stats` 가 늘 나란히 찍는다 |
| 7-10 | **`turn_duration` 이 아예 없는 작업** | `PureMs = 0` · `Warn` 에 `순수시간없음`. `--metric pure` 표본에서만 뺀다 |
| 7-11 | **증분 스캔이 놓치는 꼬리** | `scanstate.json` 에 파일 **크기 + mtime + 마지막으로 읽은 바이트 오프셋**을 적고, 크기가 줄었거나 mtime 이 과거로 갔으면 그 파일만 전체 재읽기. 스키마 판이 바뀌면 전부 재스캔 |
| 7-12 | **여러 프로젝트 섞임** | 레코드에 `Project`(cwd) 를 넣고 `scan` 기본은 **지금 폴더의 슬러그만**. `--all` 로 전부, `--project` 로 고른다 |

### 9-3. 시험 자료 익명화 규칙

실물 JSONL 조각을 `testdata/` 에 넣을 때 **아래를 다 지운 뒤** 넣는다. 이 규칙을 `testdata/README.md` 에도 박는다.

1. `message.content` 는 **통째로 지우고** `"[삭제]"` 로 바꾼다 (본문은 시험에 필요 없다 — 재는 것은 `usage` 와 시각뿐).
2. `cwd` · `gitBranch` · 파일 경로는 `C:\\proj` 같은 가짜로 바꾼다. 사용자 이름·메일·집 경로 금지.
3. `sessionId` · `uuid` · `requestId` · `message.id` 는 **모양만 지키고 값을 새로 만든다** (`req_test0001` 등).
4. `meta.json` 의 `description` 은 분류 시험에 필요하므로 **분류 낱말만 남긴 가짜 문장**으로 새로 쓴다.
5. 넣기 전 `effort`(또는 grep) 로 `sk-`·`ghp_`·`AKIA`·`@` 를 한 번 훑고, **걸리면 그 조각을 안 쓴다.**
6. 시험은 `t.TempDir()` 사본에만 돌린다. 실제 `~/.claude` 를 가리키는 시험을 만들지 않는다.

## 11. 못 정한 것

- 큰 세션에서 JSONL 합이 `cost-state` 보다 45% 적은 **정확한 까닭** (조사에서도 못 밝혔다). 설계는 「배분하지 않고 나란히 보여준다」로 피해 갔다.
- `spawnDepth ≥ 2` (서브의 서브) 기록 자리. 지금 구조는 파일이 있으면 자동으로 잡히지만 **실물을 못 봤다.**
- compaction 이 일어난 세션의 토큰 기록.
- 크기 배율 `S/M/L/XL` 값은 **첫 실측 뒤 다시 잡아야 한다** — 지금 값은 어림이다.
- 여러 기계(미니PC 포함)의 기록을 합칠지. 지금은 기계 하나 기준이다.
